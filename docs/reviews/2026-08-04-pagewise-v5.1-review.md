## 0. 结论

这一轮有两条互不相干的线，得分开说。

**线 A：分发。** 上一轮审计出的三个问题只修了一个。剩下两个的后果是：**大多数人拿不到这个产品，拿到的人打不开它。** 严格地说，这比任何功能都重要——装不上的产品，功能价值是零。但其中的签名/公证卡在你的 Apple 账号上，我做不了。

**线 B：5.0 自己留下的洞。** 复查 5.0 时发现一个硬缺口：**扫描件根本标不了**（§2，V34）。而扫描件恰恰是 PageWise 花了视觉调用去处理的那类文档。这是我造出来的洞，且能马上补。

建议：**5.1 做线 B**（完全可动手，且是修自己的缺陷），线 A 的平台矩阵单独立项、签名等你配好凭据。理由见 §4——不是因为线 B 更重要，而是因为线 A 里能立刻动的那一半需要真机验证，掺进功能版本里会两头都做不干净。

## 2. 扫描件标不了 · V34

5.0 的标记入口是**选中文字**：`useAskSelection` 要求文本层里有一段非折叠选区，`markButton` 还额外要求 `doc.kind === "pdf"`。

而文本层来自 pdf.js 的 `getTextContent()`。扫描件没有文本层，于是没有 run，没有选区，**没有标记**：

```
scanned.pdf   前 1 页可选中的文本 run 0   （needs_vision 1/1 页）
attn.pdf      前 1 页可选中的文本 run 0   （needs_vision 1/1 页）
paper.pdf     前 5 页可选中的文本 run 132 （needs_vision 0/117 页）
```

这意味着：**PageWise 花钱做视觉索引的那些页，恰恰是一个字都标不上的页。** 同样标不了的还有图、图表、以及任何非文字内容——读者最想圈出来的东西。

### 补法：拖拽框选一块区域

按住拖出一个框，就是一个标记。不依赖文本层，因此扫描页、图、表全都能标。

需要的东西**全部现成**：

| | 现状 |
|---|---|
| 屏幕矩形 → 页面矩形 | `clientRectToPageRect`，旋转页正确，已测 |
| 页面矩形 → 屏幕框 | `pdfRectToBox`，比例坐标，已测 |
| 框内取文字 | `extract_region`（5.0 的选区引用已经在用，含表格） |
| 存储 / 图层 / 列表 | 5.0 的 `Mark` 结构原样适用（`rects` 就是一个矩形） |

扫描页上 `extract_region` 取不到文字，快照为空——这是可以接受的：**几何锚点仍然准确**，快照本来就只是给人看的兜底（这正是 5.0 定下的那条界线）。区域标记在扫描页上退化成"位置 + 你写的话"，而那已经比"完全不能标"好得多。

一处要定的：拖拽与现有的文字选区如何共存。倾向**按住修饰键拖拽**进入框选，不改默认的选字行为——新增一个手势，不动一个既有手势。

## 3. 5.0 的另外三个小缺口

### 3.1 "总结一下我标的内容"要花掉一堆页读

`document_outline` 只报 `pagesWithMarks`（压缩后的页码区间）。模型要拿到标记内容，只能去**读那些页**——20 个标记散在 20 页上就是 20 次页读，而标记文本本来就在内存里、一次性拿出来只有几 KB。

补法：`document_outline` 直接带上标记本身（带上限），不只是页码。与 4.4 的 `links` 是同一个形状，`withPageMarks` 现成可复用。

### 3.2 自己写的批注搜不到

⌘F 走 `searchDocumentPages`，索引的是页文本。**用户自己写的批注不在任何索引里**——攒到 50 条以后，"我在哪儿写过那句话"没有答案。

补法：**在标记侧栏加一个过滤框**，而不是把批注塞进文档搜索。文档搜索的语义是"文档里有什么"，混入用户自己的话会让命中结果的来源变得含糊——和 4.3 拒绝把页眉留在正文、4.4 拒绝把链接塞进正文是同一条判据。

### 3.3 标记导不成单独一份

标记只出现在整份文档导出的末尾。而"我这次读出来的东西"本身就是一份独立产物，混在几万字正文后面等于没有。

补法：导出菜单加一项"仅导出标记"。`marksSection` 已经写好，抽出来复用即可。

## 4. 为什么建议先做线 B

不是因为线 B 更重要——**线 A 更重要**，装不上的产品功能价值为零。理由是可动手性：

- 线 A 的签名/公证**必须**等你把 Apple 证书和 App-specific password 放进 repo secrets，我在这儿做不了。
- 线 A 的平台矩阵能动，但要做对就得真在 Windows/Linux 上编译验证（keyring 的三套后端、pdf.js 资源路径、`tauri.conf.json` 的 `bundle.targets` 分平台化），这在当前环境里验不了，只能靠 CI 来回试。把它掺进一个功能版本会两头都做不干净。

所以：**5.1 = §2 + §3**，全部可动手、全部是修 5.0 自己的缺陷；线 A 的平台矩阵单独一版认真做，签名等你。

如果你的判断是分发更急，那就反过来——我先开平台矩阵那一版，功能往后排。这个优先级该你定，我只把两边的代价说清楚。

## 5. 本轮考虑过、不做的

| | 理由 |
|---|---|
| 让陈旧标记可以"消除标记" | 那个提示陈述的是事实（文件确实变了）。允许一键清掉，只是把一句真话藏起来，不是修好它 |
| 标记随文本重排自动重定位 | V33 的 76% 失败率，5.0 已经否掉过 |
| 图片文档的标记 | 图片没有页面几何这一层，且 `extract_region` 不适用。收益小，代价是另一套坐标口径 |
| 把批注并进文档搜索 | §3.2：会让命中结果的来源变含糊 |
