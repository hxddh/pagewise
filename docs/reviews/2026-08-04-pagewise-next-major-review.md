# 下个大版本复查：读完之后，什么都没留下

日期：2026-08-04 ｜ 基线：4.4.0（已发布）
实测编号接续 `2026-08-04-pagewise-v5.0-design.md`（V1–V32）。
多文档已按要求推迟，本文不再讨论它。

---

## 0. 复查结论

本轮复查了两个候选，一个被实测否掉，一个成立。

- **候选 A：点击引用跳到被引用的原文并高亮**——直觉上是"让用户能核对模型"的最短路径。**实测否掉**：两个提取路径对同一页的文字并不一致，整句引文只有 24% 能定位，最宽松的前 15 字锚点也只有 71%。见 §1。
- **候选 B：把 PageWise 从"问答界面"变成"读得下去的工作面"**——高亮、批注锚在页面几何上，持久化，并且模型看得见。**成立**：几何锚点稳定（这正是候选 A 缺的），且双向换算在 4.1 就已经写好并测过。见 §2。

顺带记录：`docCache.list()` 已存在；`index-queue` 已按 path 分片——这些属于多文档那份评估的补充。

## 1. 候选 A：引用跳原文 —— 实测否掉 · V33

### 想做什么

模型答案里已经有页码引用（`remark-page-refs` 把"第 5 页"变成可点链接，跳转预览），系统提示也要求"短引文逐字引用"。那么点击引用时，除了跳到第 5 页，顺手把那句引文在页面上高亮——4.1 的搜索高亮机制（`matchingItems` / `pdfRectToBox` / `highlightBoxes`）原样可用，看上去几乎白捡。

### 为什么不成立

引文来自 `extract_pages_markdown`（页文本），而高亮位置来自 `extract_text_with_positions`（文本 run）。**这是两条不同的提取路径，对同一页的文字并不一致。**

`paper.pdf` 前 40 页，取所有 ≥25 字符、非表格行的正文行当作"引文"，共 431–444 行：

| 匹配方式 | 命中 | 比例 |
|---|---|---|
| 整行在某个 run 里 | 42 | 9% |
| 整行在"所有 run 按序拼接"里 | 95 | 21% |
| 再忽略全部空格 | +10 | 24% |
| **仍然找不到** | **339** | **76%** |

放宽成"只锚定引文开头"（并额外剥掉斜体标记）：

| 锚点长度 | 命中率 |
|---|---|
| 前 15 字 | **71%** |
| 前 25 字 | 59% |
| 前 40 字 | 51% |
| 前 60 字 | 45% |

失败的样本说明了原因——两条路径对符号与数学的处理不同：

```
MISS  die kugeloberfläche *s²* lässt sich durch strecken, stauchen …
MISS  es wird ein sicherer umgang mit den quantoren (*8; 9*), mengenschreibweisen (*[; \; n;;;*r …
MISS  definition 1 ein topologischer raum ist ein paar (*x;* t) bestehend aus …
```

命中的引文平均跨 **25.7 个 run**，也就是说"一句话对应一个文本 run"这个前提本来就不成立。

### 判断

这个功能的**全部意义是让用户核对模型有没有编**。而它会在四分之一到一半的引用上静默失败，且失败集中在最需要核对的内容（公式、符号、定义）上。**没有高亮会被读成"模型编的"**——一个用来建立信任的功能，做成这样是在消耗信任。

保留说明：4.1 的搜索高亮不受影响，它的输入是用户手打的短查询，本来就是尽力而为、匹配不上就不画。同样的尽力而为逻辑可以顺手接到引用点击上（成本极低，复用现成机制），但**它不构成一个大版本**，也不该被宣传成"跳到原文"。

样本局限已知：`paper.pdf` 是数学教材，属于最坏情形；散文类文档命中率会更高。但上限由两条提取路径的分歧决定，而分歧是结构性的，不是这一份文档的特例。

## 2. 候选 B：读得下去的工作面

### 现状

PageWise 今天是一个纯问答界面。读、问、答，关掉文档之后留下的只有一条聊天记录。没有任何办法在文档上**留下痕迹**：划一句话、写一条批注、标记"这里存疑"、把三处相关的段落串起来。

导出是有的（文档转 Markdown、对话转 Markdown、模型润色的摘要），但**没有一样是锚在文档上的**——导出的是会话，不是这份文档上积累的理解。

对于一个定位在"本地文档 agent"的产品，这是比"一次只能读一份"更早被撞到的墙：用户第二次打开同一份合同时，第一次读出来的东西一点都不在。

### 为什么这次的锚点是可靠的（与 §1 正相反）

候选 A 死在文本锚点上。高亮和批注锚的是**页码 + 页面比例矩形**——几何，不是文字。它不经过任何提取路径，因此：

- 不受两条提取路径分歧的影响；
- 不受上游版本升级导致文本变化的影响（我们不固化 `pdf-inspector` 版本，这一点尤其重要）；
- 缩放、DPR、窗口大小都不用重算——4.1 已经为此选了比例坐标。

### 地基已经在了

| 需要的东西 | 现状 |
|---|---|
| 屏幕选区 → 页面矩形 | `clientRectToPageRect`，旋转页也正确（4.1 修过），已测 |
| 页面矩形 → 屏幕框 | `pdfRectToBox`，比例坐标，已测 |
| 选区取文字 | `selectionQuote` → `extract_region`，含表格 |
| 覆盖层渲染 | `SearchHighlight` / `LinkLayer` 两个现成范例 |
| 持久化 | `@tauri-apps/plugin-store`，`allowed-paths.json` 与索引存储都在用 |
| 文件变更检测 | `file_stamp_cmd`，索引存储已用它判失效 |

**不需要新的 Rust 命令，不需要新依赖。** 这是选它的主要理由——和 4.4 一样，是"数据/机制已经在了，把路造出来"。

### 必须同时造好通往模型的路

4.3、4.4、以及多文档那份评估，三次都指向同一条教训：造了能力不造路，等于没造。这一版对应的是：

- **模型要能读到批注**。用户标出来的段落，是他关心什么的最强信号。`document_outline` 里给出有批注的页，读页时带上该页的批注文本——与 4.4 的 `links` 完全同构。
- **模型要能创建批注**？——**不做**。让 agent 往用户的文档上写东西，是一个需要另外一整套确认与撤销语义的东西。这一版模型只读。
- **导出要带上批注**，否则积累的东西仍然带不走。

### 需要想清楚的一处

批注的文字从哪来：选区的 `extract_region` 结果（可能与页文本不完全一致），还是用户自己打的字？倾向：**存几何 + 存当时取到的文字快照**。快照让批注在文件被替换、页面重排之后仍然可读——哪怕矩形已经指错了地方，用户至少还看得见自己当初标的是什么。这正是候选 A 学到的教训的反向应用：**不要在需要正确的地方依赖文本匹配，但要在可以降级的地方保留文本作为兜底。**

## 3. 本轮复查发现的其他事实（不构成版本内容）

- `docCache.list()` 已存在且无调用点——多文档做起来时它就是现成的入口。
- `index-queue` 的四张表全部按 path 分片（已补记进多文档评估的 V32）。
- `pdf.ts` 的 `MAX_PDF_BYTES_CACHE = 3`：字节缓存早就是三份，而 `PDFDocumentProxy` 只有一份。
- `usage-tracker` 的 `docVisionCalls` 随会话内打开过的文档数增长，不清理——量级是每份一个整数，可以不管，记录在案。

---

## 4. 建议

下一个大版本做 **候选 B**。它不依赖多文档，也不与之冲突——批注锚在单份文档上，将来多文档来了直接就是多份各自的批注。

候选 A 里唯一值得做的那点（点击引用时顺手尽力高亮）成本极低，可以搭在任意一个版本里，但不要单独立项，也不要按"跳到原文"来承诺。
