# PageWise 4.3 评估：井快见底了，剩下的两件有证据

日期：2026-08-03 ｜ 基线：4.2.0（已发布）
实测编号接续 `2026-08-03-pdf-inspector-validation.md`（V1–V19）。

前提不变：不考虑历史兼容；陈旧依赖直接删；不为"用满能力"而堆架构。

---

## 0. 先说结论：这轮很小，而且应该很小

四轮下来，`pdf-inspector` 的可用面已经基本吃完：

- **上游没有新版本**。仍是 0.1.7，与 4.0 集成时同一个版本。不固化版本的收益这轮是零——没有新能力可吃。
- **模型产出已全部有消费方**。4.2 删掉最后两个无人读取的字段之后，`has_table` / `needs_vision` / `title` / `outline` / `links` / `figures` 全部在用。
- **剩余未用的上游 API 都有否定证据**：结构化表格（需 TSR 模型）、标记结构树（够不着 lopdf）、`MarkdownProfile::Compact`（省 0.0%）、自建文本层（换不来什么）。本轮无新证据推翻任何一条。

本轮新测了两个此前没碰过的 markdown 选项，一个不成立、一个不该用（§3）。真正剩下的是**两件有实测支撑的事**，都不新增命令、不新增依赖。

如果这两件做完，我认为围绕 pdf-inspector 的工作就到头了；再往后的产品提升应该来自别处，而不是继续从这个库里榨。

## 1. 运行页眉污染搜索与上下文 · V20

`extract_pages_markdown` 把运行页眉当正文交出来。`paper.pdf` 第 10 页的**第一行**就是：

```
<u>1.2. METRISCHE RÄUME</u>
```

全档统计：117 页里，**20 种**重复出现 ≥3 次的首/末行，覆盖 **80 个页次**。

危害不在 token（占比不到 2%），在**搜索精度**：

| 查询 | 命中行 | 其中是页眉/页脚 |
|---|---|---|
| `Kompaktheit` | 5 | **3** |
| `Metrische` | 25 | 3 |

用户按章节名搜索——恰恰是导航时最常输入的东西——**多数命中可能是页眉**。4.2 刚做的命中高亮会忠实地把这些页眉标出来，用户点进去发现是页顶的一行装饰。

上游有 `MarkdownOptions.strip_headers_footers`，但这条路走不通，两个原因：

1. **实测无效**：在 `paper.pdf` 上开启后删除了 **0 行**（155,844 → 155,844 字符）。
2. **我们的路径根本用不上它**：`extract_pages_markdown` 不接受任何 options（这也是 4.1 加密路径被迫另起一条提取形状的同一个限制）。

→ 自己做。检测规则窄而明确：一行同时满足**是某页的首行或末行**、**在 ≥3 页的同一位置重复**、**长度 < 80 字符**，才从那些页的那个位置删掉。纯函数，逐条可测。

不做成"删掉所有重复行"——正文里合法重复的短行（表头、"续表"）不该被吃掉。

## 2. `read_figure` 现在无从被发现 · 本轮审计

4.1 加了 `read_figure`，但**没有任何东西告诉模型某页有图**：

- `document_outline` 报 `pagesWithTables`，**不报图**；
- `figures` 只在 `read_figure` 内部被读；
- 系统提示只有一句"图或扫描页会让搜索失效"，没说有工具可以看图。

于是模型只能盲猜着调用，或者根本不调用。**这是我自己在 4.1 留下的缺口**：造了工具，没造通往它的路。

→ `document_outline` 增加 `pagesWithFigures`，与 `pagesWithTables` 完全对称。数据已在模型里，零新增解析。

---

## 3. 本轮测了、但不做的两个选项

### 3.1 `strip_headers_footers` —— 实测无效

见 §1。开启后 0 行变化，且我们的提取路径不接受 options。

### 3.2 `include_images: true` —— 有效，但不该用

实测：`paper.pdf` 加入 **20 个** `![Image: Im2](image)` 占位符，文本 +0.1%。

它确实解决了 §2 的问题——模型能在正文流里看到"这里有张图"，而且带位置。但代价是把元信息塞进正文：

- 占位符会进 **⌘F 搜索**（`markdownToPlainText` 把 `[label](url)` 归一成 label，于是搜索里出现 `!Image: Im2` 这种噪音）；
- 会进**导出的 Markdown**，用户拿到的文档里多出 20 个无意义的图片链接；
- 会进 **agent 每一次页读**的上下文。

而 §2 的做法把同一信息放在元数据里，一处也不污染。**选 §2，不选这个。**

## 8. 实施记录（2026-08-04）

两项均已落地。实测效果（`paper.pdf`，117 页）：

| | 剥离前 | 剥离后 |
|---|---|---|
| 总字符 | 155,844 | 152,821（−1.9%） |
| 搜索 `Kompaktheit` 命中行 | 5 | **3** |
| 搜索 `Metrische` 命中行 | 25 | 23 |
| 第 10 页首行 | `<u>1.2. METRISCHE RÄUME</u>` | `## Also für n = 1:` |
| 大纲条目 | 78 | **78** |

### 实施中发现并修正的一处误伤

第一版规则把 **"Lösungen der Übungsaufgaben" 从大纲里删掉了**——它既是章节标题，又在其后的页面上作为运行页脚重复出现（实测 5 次）。按"重复即页眉"的规则，它被当成装饰剥掉了，于是整章从导航里消失。

修正：**标题永远不算装饰**。提取器按字号把一行提升为 `#` 标题，那它就是结构，无论重复多少次。加了针对这个具体文档情形的回归测试。

这也是为什么本轮没有只跑合成用例就收工——78 → 77 这个差值只有拿真实文档对照才会暴露。

### 评审指出的第二处误伤：跨页表格的表头行

§1 里写了"表头不该被吃掉"，但第一版实现只豁免了标题。**跨页续排的表格会在每页顶部重复表头行**——`| Year | Revenue |`——完全符合"首行 + 重复 ≥3 页 + 短"的规则。剥掉之后，`|---|` 分隔行和下面每一行数据都失去了列名，页读和搜索结果里的数字变成无法解释的裸值。

修正：**表格行与标题同属结构**，一并豁免（`is_structural_line`：行首为 `#` 或 `|`）。加了跨页表格的回归测试。

在 `paper.pdf` 上重测，各项指标与修正前完全一致（152,821 字符 / 命中 3 与 23 / 大纲 78）——这条豁免在该文档上不产生任何差异，纯粹是防御。

### 剩余的页眉

剥离后 `Kompaktheit` 仍有 3 条命中（原 5 条中有 3 条是页眉，正文 2 条）。差额来自一条刻意的保守规则：**内容少于 3 行的页面不参与剥离**，以免把一页删空。这些稀疏页上的页眉得以保留。宁可漏剥，不可删空。
