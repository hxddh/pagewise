# PageWise 4.1 设计：把已经在手的数据用起来

日期：2026-08-03 ｜ 基线：4.0.0（已发布）
本轮实测记于 §4，编号接续 `2026-08-03-pdf-inspector-validation.md`（V1–V16）。

前提不变：不考虑历史兼容；陈旧依赖直接删；不为"用满能力"而堆架构。

---

## 0. 一句话

4.0 把文档解析收成了一次调用，但**产出的东西有一半还没人消费**——大纲只有 agent 在用、链接和图区解析出来就躺着、位置信息压根没进模型。4.1 不新增解析，只把已经在手的数据接到界面和工具上。

新增命令 **1 个**（`page_text_items`）。

---

## 1. 做什么（五项，全部有本轮实测支撑）

### 1.1 ~~加密 PDF 输入密码~~ —— 已按指示去掉

> **2026-08-03 决定：不做。** 实现过一版并通过全部测试，随后按"不用考虑加密文档"的指示撤销。
>
> 撤销的收益不只是少一个功能：这是本轮唯一一处架构妥协。`extract_pages_markdown` 不接受 options 也就不接受密码，加密文档只能走"整档提取 + 按页标记切分"这条**第二种提取形状**——实测该切分与逐页路径在 117 页里只有 10 页完全一致。既然加密文档不在使用场景里，这条分支就是没有理由的复杂度。去掉后提取路径重新只有一条。
>
> 下面保留原始评估，作为将来若需要时的依据。

#### 原始评估 · V15

今天 PageWise 对加密 PDF **只试空密码**，失败就打不开。银行流水、工资单、对账单大量是加密的。

实测（自造 RC4-40 加密样本，用户密码 `secret`）：

```
无密码   → Err(Encrypted)
正确密码 → Ok(1 页, "## Encrypted PageWise fixture")
错误密码 → Err(Encrypted)
```

三态可区分，正好够做交互：打开失败且错误是 `Encrypted` → 弹密码框；密码错 → 同一个框提示重试。

改动：`open_document(path, password?)`，`PdfOptions.password` 直传；前端一个密码输入框。**密码只在内存里传给这一次解析，不落盘、不进 keychain**——keychain 是给 API key 的，文档密码进去等于替用户长期保管别人的机密。

### 1.2 搜索命中在页面上高亮 · V16

今天 ⌘F 的结果点进去只是 `onJumpToPage(hit.page)` ——跳到第 42 页，然后用户自己找。

实测用 `TextItem` 定位命中，中英文都精确：

```
"1,284"        → p1 x=105.8 y=654.0 w=32.3 h=12.0
"Kompaktheit"  → p18 x=90.1 y=437.1 w=117.7 h=14.3  "1.5 Kompaktheit"
"未经审计"      → p1 x=33.8 y=598.5 w=292.7 h=10.5
```

~~23,107 个文本 item 里几何缺失的是 0 个。~~ **该数据有误，2026-08-03 更正**：那次测量实际跑在 `cjk.pdf`（12 个 item）上，`paper.pdf` 的输出被过滤截掉了。逐样本重测后 `paper.pdf` 有 **75 个零宽 item**（占 0.3%），会画出看不见的高亮框。详见 `2026-08-03-pagewise-v4.2-design.md` §0。

诚实的粒度说明：item 是**行/文本段级**的，不是逐字符的。高亮框覆盖的是命中所在的那一行，不是那几个字——因为逐字符推进宽度上游没给。这仍然远好过"跳到第 42 页自己找"，但不该说成"精确到字"。

这一项需要**唯一的新命令**：

```rust
page_text_items(path, page) -> Vec<{ text: String, rect: Rect }>
```

按页懒取（整档 23k 个 item，单页约 200 个），不塞进 `DocumentModel` —— 模型是打开文档时一次性付出的代价，不该为一个偶尔用到的功能背上这个体积。

### 1.3 大纲侧栏 · V12

`outline` 4.0 就在文档模型里，agent 已经在用，**界面还没消费**。一份 117 页教科书零书签，用户今天只能靠缩略图翻。

复用现成的 `ThumbnailSidebar` 布局，加一个大纲页签；点条目跳页。零新增数据、零新增调用。

### 1.4 预览层可点击链接 · V14

`links`（含 URL 与 bbox）已在模型里，`pdfRectToTopLeft` 已经写好。缺的只是一个覆盖层组件：绝对定位的透明锚点，点击走已有的 `tauri-plugin-opener`。

外链点击**必须先确认**——文档里的 URL 是不可信输入，静默打开浏览器不行。

### 1.5 `read_figure` agent 工具 · V14

`figures` 的 bbox 已在模型里。今天用户问"图 2 说明了什么"，agent 只能把**整页**渲成 1568px JPEG 发出去；插图之外的正文一起进了视觉模型，既贵又稀释。

新工具 `read_figure(page, index)`：按 bbox 裁剪该页渲染结果，只发那一块。裁剪在前端做——`renderPageToJpegBytes` 已经在了，加一个裁剪框即可，**不需要新的 Rust 命令**。

> 这不是 4.0 里被我撤回的那条"图区裁剪送 vision"。那条说的是索引管线自动裁剪，不成立（需要 vision 的是扫描页，图就是整页）。这条是用户**显式问某张图**时按需裁剪，场景完全不同。

### 1.6 删掉两个零引用的 crate

```
image     = "0.25.10"   src-tauri/src/ 中引用数：0
tempfile  = "3.27.0"    src-tauri/src/ 中引用数：0
```

`image` 的活早就搬到前端 `image-transcode.ts` 了，`tempfile` 是更早的遗留。二进制会再小一截。

## 2. 不做什么（四项，各自有否定证据）

写在这里是因为它们听上去都像"充分利用能力"，但实测都不成立。

### 2.1 结构化表格（`extract_tables_with_structure_cells_mem`）—— 死路

`TsrTableInput` 的字段注释写明：`structure_tokens` 是"**TSR 模型**输出的原始结构 token"。PageWise 没有表格结构识别模型，接它等于引入一个 ML 依赖——同时违反"架构简化"和"本地处理"。

唯一的免模型替代是 `detect_vector_grid_in_region_mem`（从矢量线条推网格）。实测在 6 个页面上跑：

- **5 页未检出**——包括 `cjk.pdf` 那张真表格（CSS 边框），以及多数 LaTeX 表格页（booktabs 只有横线）
- **1 页检出，但是误报**——数学证明页被当成 6×2 表格，单元格内容是打乱的散文：`"TY = und jedem dY gegeben . (U Beh. (U (f ( Teilmenge"`

漏真表、造假表。而 4.0 已有的 Markdown 表格覆盖的是通用情况。**不接。**

### 2.2 标记结构树（`structure_tree`）—— 够不着

`StructTree::from_doc(doc: &lopdf::Document)` 需要一个 lopdf `Document`，而 `pdf-inspector` **没有再导出 lopdf**。要用它就得把 lopdf 加成直接依赖——等于在刚删掉一个 PDF 解析器之后再引入第二个。**不接。**

### 2.3 `MarkdownProfile::Compact` 省 token —— 名不副实

实测两份真实文档：

```
paper.pdf  Fidelity 155,844 → Compact 155,841   省 0.0%
cjk.pdf    Fidelity 156     → Compact 156       省 0.0%
```

它只折叠长点线 leader，而 4.0 用的 `is_garbage_text` 早就把点线 leader 豁免掉了。**不是一个可用的省钱开关。**

### 2.4 用 TextItem 自建文本层替换 pdf.js 的 —— 换不来什么

想法是消除"搜索用的文本"和"选择用的文本"两套来源。但：

- item 是行/段级的，pdf.js 的 span 也是——粒度上没有优势；
- pdf.js **无论如何都要留着**（渲染、缩略图、viewport），删不掉依赖；
- 换掉的是一段已经处理好旋转、RTL、字形缩放的工作代码。

拿风险换一致性，而这份一致性在 4.0 的框选提问路径上已经用区域提取补上了。**不做。**

          ─────────────   ──────────────   ─────────────────

依赖：**净减两个 crate**，不新增。

## 4. 本轮实测（V15–V16，接续既有编号）

### V15：加密 PDF 三态可区分

自造 RC4-40 加密 PDF（`/V 1 /R 2`，用户密码 `secret`，手写算法 3.2/3.3/3.4，845 字节）：

| 调用 | 结果 |
|---|---|
| `process_pdf` | `Err(Encrypted)` |
| `process_pdf_with_options(password="secret")` | `Ok(1 页, "## Encrypted PageWise fixture")` |
| `process_pdf_with_options(password="wrong")` | `Err(Encrypted)` |

→ 可以据此驱动"弹框—重试"交互。**该结论作废于同日**：加密文档不在使用场景内，夹具与实现均已移除（见 §1.1）。

### V16：命中定位可行，粒度是行级

`extract_text_with_positions` 在 `paper.pdf` 得到 23,107 个文本 item，**几何缺失 0 个**；在 `cjk.pdf` 得到 12 个。逐条查询均能定位（见 §1.2）。

item 的粒度是行/文本段，例如 `"本报告涵盖二〇二六年七月至九月的经营情况。营业收入同比增长百分之十二点五。"` 是**一个** item（w=388.5）。→ 高亮到行，不到字。

整档取位置耗时 739 ms（117 页），因此按页懒取而不是打开时全取。

### V17：两个 crate 已无引用

`grep -rn "image::|tempfile::" src-tauri/src/` → 各 0 处。
