# 5.2 评估：这一版该做分发，而且它比看上去容易

日期：2026-08-04 ｜ 基线：5.1.0（已发布）
实测编号接续 `2026-08-04-pagewise-v5.1-design.md`（V1–V35）。

---

## 0. 结论

**建议 5.2 做平台矩阵。** 上一轮我把它排在功能后面，理由是"验不了、得靠 CI 来回试"。本轮把代码翻了一遍，那个顾虑站不住：**Rust 侧本来就是跨平台的，不是需要移植，只是从来没有构建过。**

功能这条线本轮也审了，找到一个真缺口（§3），但它小，且不急。

---

## 1. 为什么说"本来就是跨平台的" · V36

逐条查证，不是估计：

| | 现状 |
|---|---|
| 平台相关代码 | **零处**。`src-tauri/src/*.rs` 里没有一个 `#[cfg(target_os = …)]` |
| 密钥后端 | **三套已经全部编进去了**：`keyring` 开着 `apple-native` + `windows-native` + `sync-secret-service` |
| Windows 图标 | `icon.ico` 在 |
| Linux 图标 | `32x32.png` / `128x128.png` 在 |
| Windows lib 名冲突 | `Cargo.toml` 里已经处理过（`pagewise_lib`，注释直接写着"only an issue on Windows"） |
| 前端构建 | 纯 node/vite，无平台假设 |

也就是说：**这个项目一直是照着三平台写的，只是 CI 从来只在 macOS 上按过一次快门。**

### 真正要改的三处

1. **`bundle.targets` 写死了 macOS**
   ```json
   "targets": ["dmg", "app"]
   ```
   即便换成 Windows runner 也只会尝试出 dmg。要改成分平台（或 `"all"`，由 Tauri 按当前平台挑）。

2. **`verify:bundle-version` 只认 macOS 产物**
   `scripts/verify-bundle-version.mjs` 读的是 `bundle/macos/*.app` 的 Info.plist。在 Windows/Linux 上必然失败——这一步要么按平台跳过，要么各平台各写一套校验。

3. **`release.yml` 只有一个 job**
   `build-macos` 要变成 matrix，且"创建 Release"这一步只能跑一次（否则三个 job 互相覆盖 release body）——通常拆成"各平台构建并上传 artifact" + "一个汇总 job 建 release"。

### 已知的真实风险（不粉饰）

- **Linux runner 要装系统库**：webkit2gtk / libdbus（`sync-secret-service` 依赖它）。这正是本容器里 `cargo check` 跑不了的同一批依赖。装是常规操作，但第一次多半要试几轮。
- **我验不了产物本身**。我能保证的只有"CI 上编得过、打得出包"，装上去能不能跑、Windows 上密钥能不能存进 Credential Manager，得你在真机上试。这条必须说在前面。
- 三平台构建会让每次发布从 ~8 分钟变成 ~15–20 分钟。

## 2. 签名与公证：仍然卡在凭据上

不变：仓库里 `signingIdentity` / `APPLE_` / `notariz` / `codesign` **零命中**。未签名的 DMG 在别人机器上会被 Gatekeeper 拦成"已损坏"。

这件事我做不了，需要你把证书和 App-specific password 放进 repo secrets。**它和 §1 是可以分开的**：先出三平台的包，签名后补——Windows 和 Linux 那两个包不受 Gatekeeper 影响，等于立刻就有两个平台的用户能真正用上。

---

## 3. 功能线本轮找到的缺口：标记与 agent 只通了一个方向

5.0/5.1 之后，**模型能读标记，用户却不能就着标记提问**。

- 选中文字有"就这段提问"（3.5.6 起就有）
- 标记的批注卡片上只有"写点什么"和"删除"
- 区域标记更彻底：扫描页上的框**根本没法重新选中**，因为那里没有文本层——用户想问"这张图是什么意思"，只能自己描述位置

也就是说：读者最在意的那几处（他亲手标出来的）反而是最难拿去提问的。

补法很小：批注卡片加一个"就这条提问"，把快照（或区域标记的话，把 `read_figure` 的落点页码 + 矩形）带进输入框。**区域标记的情况正好能接上 4.1 就写好的 `read_figure`**——框已经是一个矩形，`renderRegionToJpegBytes` 现成。

但这属于"锦上添花"，不是"没它就用不了"。**优先级低于 §1。**

## 5. 建议

**5.2 = 平台矩阵**（§1）。理由三条：

1. 这是唯一"不做就没人用得上"的问题；
2. 代价比上一轮我估的低——不需要移植，只需要构建（V36）；
3. 与被你卡住的签名解耦：Windows/Linux 两个平台不受 Gatekeeper 影响，出包即可用。

顺手做掉两件零风险的：`verify:bundle-version` 分平台（§1.2 反正要改），删掉 `isEmbeddingCapableProvider`（§4）。

§3 的"就着标记提问"留给 5.3。

如果你更想先要功能，那就把 §3 提上来——但请知道那意味着又一版只有你自己能安装的产品。
