## 0. 结论

7.0 修了运行内重发，7.1 修了跨轮次重发。这一轮我往更细的粒度看：**同一次运行内，同一页的文本可以被完整返回两次**——没有任何东西记得"这一页我已经给过模型了"。这是目前 token 链条上剩下的最大一块。

第 4 条（UI）我要先说一句不好听的：**7.1 我建了 `Panel` 原语，然后一个调用点都没有改。** 全仓库真实使用数是 **0**，只有它自己的测试在用。同时 **79 条 CSS 规则各自定义了一遍"一个面(background + border-radius)"**。这不是评估出来的新问题，是我上一版没做完。

同样没做完的还有间距：**413 处直接写 px、只有 19 处用 `--space` token，20 种不同的值**——6.3 收敛了字号和圆角，间距一直没碰。

## 1. token · V77–V80

### 1.1 同一页可以被完整买两次 · V77

```
grep "returnedPages|sentPages|alreadyRead" src/lib/agent.ts → 无
interface ReadBudget { used, max, scans, maxScans, gen }   ← 只记总字符数，不记页
```

`ReadBudget` 只累计**字符总数**，不记录**哪些页已经给过**。于是：

- 模型先 `read_pdf_range(10, 20)`，之后又 `read_pdf_page(14)` —— 第 14 页的全文**第二次**被放进上下文并计费；
- 更常见的是 `read_section("三、风险")` 之后再 `read_pdf_page` 读同一节里的某页。

7.0 的运行内压缩只压**较早的**结果，最近 4 条保持原样——重复的那次通常就在这 4 条里。

→ 修法：给这次运行记一个"已返回页"的集合，重复请求返回一行 `[Page 14 已在本次对话中给出，见上文]` 而不是全文。**这不改变模型能拿到的信息**（内容就在上文），只是不再付第二遍。

### 1.2 保留最近 4 条工具结果 = 每步最多 2.4 万字符的地板 · V78

```
KEEP_RECENT_TOOL_RESULTS = 4
DEFAULT_PAGE_MAX_CHARS = 6_000
4 × 6,000 = 24,000 字符 ≈ 6,000 token —— 每一步都带着
```

4 是我当时随手定的。模型真正在推理的通常是**最后一到两条**；更早的即使还"在场"，也已经被它读过并总结进了自己的思路。

→ 修法：降到 2，并且**按字符预算而不是条数**来保留（例如"最近若干条，总量不超过 12,000 字符"）——一次读了 6 页的 range 和一次读了半页的 page，不该占同样的名额。

### 1.3 每个工具结果都驮着一段固定说明 · V79

```
UNINDEXED_NOTE  ≈265 字符 ≈66 token   出现在 2 类结果里
SCAN_LIMIT_NOTE ≈266 字符 ≈66 token
BUDGET_NOTE     ≈171 字符 ≈42 token   嵌在 7 处返回值里
```

这些是**给模型的指令**，性质上属于系统提示，却按"每次工具调用"重复发送。搜索现在默认 12 条命中（≈650 token），其中 66 token 是这段每次都一样的话——**10%**。

→ 修法：把常驻的那句移进系统提示（一次性，且落在缓存前缀里），工具结果只留一个短标志位（`unindexed: true`）。**只有真正随情况变化的那句**（配额用尽、预算耗尽）才留在结果里。

### 1.4 一处我查过、结论是不用改 · V80

`yield-to-ui`、`agent-stream-idle` 的定时器、视觉扫描的 1568px/0.85 参数、系统提示 1563 字符——都复查过，都合理。写在这里是因为你要求"每个环节"。

## 2. 会话 · V81

7.1 之后已经有：计划视图、步骤耗时、可点击的步骤、可中途转向、用量与缓存可见。对照 Codex / Cursor / Dia，还缺三件：

1. **答完之后没有下一步。** Dia 和 Cursor 都会在答案末尾给 2–3 个可点的追问；这里答完就是句号，读者要自己想下一句问什么。文档场景下这条特别有价值——"这一节和第 40 页的结论是否一致"这种问题，代理比读者更知道值得问。
2. **不能从某一轮分叉。** 可以编辑重发（会覆盖后续），但不能"保留原来那条、另开一支"。
3. **对话本身不能用键盘走。** 上下键在输入框里是移动光标，没有"跳到上一条回答/下一条引用"。命令面板覆盖了全局动作，唯独对话内部没有。

→ 修法：第 1 条最有价值也最便宜——**追问由代理在答案末尾以结构化形式给出**（`Output` 能力，见 §3），不额外发一次请求。第 2、3 条排在后面。

## 4. UI：我上一版建了个没人用的组件 · V83

```
<Panel> 真实调用点：0（只有 Panel.test.tsx）
自己定义一个"面"(background + border-radius)的 CSS 规则：79 条
面板/卡片/菜单/浮层类名：46 个

间距用 --space token：19 处
间距直接写 px：413 处
不同的 px 间距值：20 种（8×87, 6×63, 12×57, 10×55, 4×43, 2×31, 14×21, 16×18, …）
```

两件事：

1. **把 `Panel` 真正用起来**——79 条自定义面的规则里，绝大多数只是"背景 + 圆角 + 边框"的重复。收敛到三种色调（surface / elevated / inset），和按钮、输入框走过的路一样。
2. **间距上刻度**。现有 token 是 4/8/12/16，而代码里 6、10、14 用得比 12、16 还多——**它们全部差 2px 不在格上**。扩成 2/4/6/8/12/16/24 七级（把 6/10/14 里的 10 归到 8 或 12），然后全量替换。

第 2 条会改变一部分视觉密度，**这是唯一一处我会主动改变外观的地方**，需要你在真机上验收。
