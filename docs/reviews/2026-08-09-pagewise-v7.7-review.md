# 7.7 评估：上一轮我把「设置层测试稀薄」说错了；真正最薄的是 hooks，而每条消息都要穿过它

日期：2026-08-09 ｜ 基线：7.6.0（已发布，含 CRLF 修复后的重新上传）
实测编号接续 `2026-08-08-pagewise-v7.6-review.md`（V1–V111）。

---

## 0. 结论

**先认账一个数字。** 7.6 评估说设置层「测试覆盖稀薄」，把 `settings.ts` 775 + `AiProviderSettings.tsx` 759 + `llm.ts` 487 = 2,021 行算成一整块。查了：**`settings.ts` 有 38 条测试、656 行测试代码，9 个 describe 覆盖迁移、keychain 回退、profile 映射、store 边界和会话密钥缓存；`llm.ts` 有 12 条。** 这两个文件是被测得相当扎实的。说它们稀薄，和上一轮「95 处硬编码尺寸」是同一个毛病：**把行数当成了覆盖率的反面，没去数**。

真正稀薄的是另外两块，其中一块比设置层危险得多：

```
src/hooks              1,954 行 / 1 个测试文件（2 条 it）
  useDocAgent.ts         657 行 / 0
  useAppCommands.ts      312 行 / 0
src/components/settings 1,525 行 / 1 个横切 a11y 测试
  AiProviderSettings.tsx 759 行 / 0
```

`useDocAgent` 是**每一条消息都要穿过的地方**——发送、重发、编辑、引导、乐观插入与回滚、持久化、abort 世代。657 行，零测试。7.6 给 `ChatPanel` 补了 7 条，那是它的调用方；被调用的那一层还是黑的。

**7.6 的引导功能有一个未验证的前提，我要写在明面上。** 它把纠正作为一条 `user` 消息追加在最后一条 tool result 之后。这个位置的安全性我只在单元测试里验证了**消息形状**（配对不被破坏），没有对着任何真实 provider 发过一次请求。OpenAI 兼容的 chat API 接受 tool 之后紧跟 user，但 DeepSeek / OpenRouter 各家转发的行为我没有证据。**这是 7.7 的第一件事，而且它是风险不是功能。**

### 1.2 hooks 是全仓最薄的一层，而它是编排层 · V113

```
src/hooks   17 文件 / 1,954 行 / 1 个测试文件（useStreamingReveal，2 条 it）
```

按风险排：

| 文件 | 行数 | 它负责什么 | 测试 |
|---|---|---|---|
| `useDocAgent.ts` | 657 | 发送 / 重发 / 编辑 / 引导 / 乐观插入与回滚 / 持久化 / abort 世代 | 0 |
| `useAppCommands.ts` | 312 | 全局快捷键与命令面板动作 | 0 |
| `useConversationKeys.ts` | 124 | Alt+↑↓ 会话导航 | 0 |
| `useDebouncedSave.ts` | 117 | 设置的防抖保存 + 卸载时兜底写入 | 0 |

`useDocAgent` 里有几处**只靠注释维持**的不变量，每一处都能安静地坏掉：

```
agentGenRef / streamAgentGenRef / sendGenRef  三个世代计数器
  → 文档切换后迟到的 chunk 不得落到新会话上（onData / onFinish / onMessagesRepaired 各自 guard）
rollbackOptimisticUser
  → 按 id 撤，撤不掉再按文本比对撤；比对用 extractUserText
steerRun
  → 排队 + 落进 transcript，两件事漏一件就是「输入框清空、答案变了、没有痕迹」
lastSendOptionsRef
  → 文档切换时必须清空，否则 A 文档的「带页面截图」选项会作用到 B 文档
```

这些正是用户报过的三个 bug（透明弹层、重新回答失效、复制失效）所在的层：**不是那层 bug 多，是那层没有任何东西能证明 bug 存在**。上一轮六个 bug 我能找出来的五个都在 `src/lib`，原因相同。

→ 这一轮该做的：给 `useDocAgent` 的每条不变量补一条测试。不是覆盖率指标，是**把注释里的承诺变成会失败的断言**。`ChatPanel.steer.test.tsx` 和 `MarkSidebar.test.tsx` 是两个可抄的样板；`useDocAgent` 要 mock 的是 `useChat`，比组件更好摆。

## 2. 会话 · V114

### 2.1 引导功能的未验证前提

7.6 的注入式引导，安全性论证是「追加在最后一条消息之后，不可能插到 tool call 和它的 result 之间」。论证成立，但它只回答了**消息序列**的问题，没有回答**provider 接受不接受**的问题：

```
prepareStep 返回的 messages 末尾追加 { role: "user", content: [{type:"text"}] }
前一条是 { role: "tool", content: [{type:"tool-result"}] }
→ 单元测试验证了配对不破（agent-steer.test.ts，19 条）
→ 没有任何真实请求验证过 DeepSeek / OpenRouter 各路由接受这个序列
```

一次真实运行就能定论：开一份 PDF，问一个要读几页的问题，读到一半发一句纠正。要么它照做，要么 provider 报错。**如果有 provider 拒绝，回退是现成的**——`steerRun` 返回 false 时 `ChatPanel` 已经会走停止重启那条路，把拒绝映射成 false 即可。

这条我在实施时**做不了**（没有 key），所以它是给你的一步操作，不是本轮任务。教训记在这里：**7.6 把一个新的网络行为当成纯逻辑验证完就发布了。**

### 2.2 复查过、没有发现缺口的

```
注入式引导 / RunPlanStrip / ToolStepsBlock 步骤+耗时 / PagesReadTrail 可点击 /
正文页码可点击 / Alt+↑↓ / 会话内搜索 / 编辑重发 / 重新回答 / 用量弹窗含缓存输入 /
标记→提问（MarkSidebar 每条标记有「就这条提问」、follow-ups 会建议、outline 会上报标记）
```

标记这条链是完整的，我本来以为是缺口，查完不是。**这一轮我在会话轴上没有强发现，就不编一个。**

（分叉已于 7.5 决定不做，不再复列。）

## 3. token · V115

维持 7.6 的判断：**副线**。结构性的四层重复已处理完，固定前缀 ≈1,269 token 且逐轮命中缓存。

两项测量仍然挂着，仍然需要真机：

1. **Anthropic 路由的 `cachedInputTokens` 是否为 0。** 静态事实已确定：全仓 `cache_control` / `providerOptions` 出现 0 次，所有 provider 走 `createOpenAI({baseURL}).chat(id)`。是 0 就值得在 `providerFetch` 里改写请求体加断点。
2. **一轮问答中页面文本的实际引用率。** 决定要不要做按需截取。

这两条从 7.6 挂到 7.7，是因为它们本来就不是仓库内能完成的任务。**继续列在待办里，但不再当成某一轮的任务项**——列成任务是排期错误，重复两轮就是没长记性。

## 4. UI · V116

7.6 做完了结构：13 个分片、层叠顺序有快照守卫、死规则/孤儿动画/可 token 化字面值三条不变量进了测试。这一轮 UI 只剩一件可测的：

```
<Button> 66 : 原生 <button> 38（分布在 22 个文件）
其中 3 个在 ui/Button.tsx 自身、1 个在 ui/Field.tsx —— 是 primitive 的实现，不算
剩 34 个分布在 20 个文件
```

6.3 已经论证过一部分是合理的（卡片形按钮会失去语义、`<details>` 的 summary、行内文字级 affordance）。问题是**没有任何机制区分「论证过的例外」和「还没搬」**——和 7.6 之前的死类名一样，是一个只存在于注释里的判断。

→ 做法照 7.6 的模板：给每个原生 `<button>` 定性，合理的在原地写明理由，其余搬到 `<Button>`；然后加一条测试，要求每个原生 `<button>` 的上一行或同一行带一个约定标记（例如 `/* raw-button: 理由 */`），没有标记就失败。**这样「例外」就必须写下理由才能存在。**
