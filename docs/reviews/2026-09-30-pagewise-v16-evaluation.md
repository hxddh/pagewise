# 16.0 评估：少一半的界面，同样的出处

日期：2026-09-30 · 基线：v15.0.0（f8e97fc）

## 0. 结论

13.0–15.0 三个大版本回答了"这句话有没有出处、出处是否成立"。能力是齐的，但代价堆在界面上：一枚引文标记有 8 种状态，一条回答下有 7 个按钮，导出有 7 种、分在 3 个地方，设置有 21 项。读者要先学会这套词汇，才能用上"可核对"。

这次深度 review 还找到 20 个经复核的缺陷。其中 5 个会**给出错误的核对结论**：小数截断了句子，一句里有多个标记，中文年份和万分之被读错；另有 2 个会**丢掉读者自己的数据**：一次写盘失败后切换文档会删掉标记和结论，切换 OCR 语言会覆盖另一种语言的识别缓存。

**16.0 不加新能力，做三件事，按优先级：**

1. **核对结论必须对**：修掉全部判错的缺陷和丢数据的缺陷，每个都加回归测试，把 numbers 评测扩到小数、年份、万/亿、千分之/万分之、条款号。
2. **读者看到三种状态**：✓ 已核对 / ! 请看原页 / ✗ 未找到。内部状态一个不删，只改给读者看的那一层。
3. **每个动作只有一个入口**：导出从 7 种变 3 种，回答下的按钮从 7 个变 4 个，设置从 21 项变 12 项以内，全产品统一用词。

目标句：**打开一份文档、问一个问题，读者不用学任何术语，就知道哪句话可以信、哪句要自己翻页看。**

## 1. 方法

- 两路代码审查（14.0–15.0 新代码；会话、智能体、存储、预览等主流程），每个缺陷都要用 vitest 或脚本复现，只靠读代码的单独标注。
- 我对影响结论和数据的缺陷逐条独立复现（见 §2 "复核"列）。
- 产品面盘点：逐个界面数控件、文案、状态。
- 界面：`npm run ui:shots` 拍 12 张主流程截图，加上 `audit:citations`、`audit:tables`、`audit:claims` 的截图，逐张评审。

## 2. 缺陷

### 2.1 P0：核对结论错误

| # | 缺陷 | 位置 | 场景 | 复核 |
|---|---|---|---|---|
| B1 | 小数点被当作句末，开头的数字被当作列表序号剥掉 | `citations.ts:127,136` `sentenceBefore` | `罚款为999.99万元〔p2〕` 被检查的句子只剩"万元"，数字不参与核对，错误金额显示为已核对；`3.5% of…` 只剩"% of…" | 独立复现 |
| B2 | 同一句里有多个标记时，后一个标记连带前半句一起检查 | `sentenceBefore` / `claimBefore` | `定金30%〔p2〕，尾款70%〔p3〕` 查 p3 时带上了 30%，于是判"数字不在原文" | 独立复现 |

## 3. 简化

### 3.1 引文：8 种状态 → 读者看到 3 种

| 读者看到 | 样式 | 覆盖的内部状态 |
|---|---|---|
| ✓ 已核对 | 紫色实线 | located；记录里的 confirmed |
| ! 请看原页 | 琥珀实线 | mismatch、unconfirmed（扫描件）、unreadable、stale |
| ✗ 未找到 | 红色虚线 | unlocated、outOfRange、retracted |

- 没有引文或还在核对的，保持灰色、不加边框，不算一种状态。
- 具体原因放在提示里，例如"12% 不在这段原文里""扫描页，文字可能识别有误"。
- 模型审阅只写进提示；审阅判"相悖"时，把标记升级为 ✗。
- 合计行改成一句："5 句已核对 · 2 句请看原页 · 1 句未找到"。现在最多有 5 个分句，而且只要有一处问题整行就变红。
- 引文标记、记录、表格 CSV 共用同一套状态词。现在 `cite.*`、`record.trust*`、`table.status*` 是三套平行文案。

### 3.2 导出：7 种 → 3 种，只有一个入口

"导出…"打开一个选择框，菜单和命令面板都指向它：

- **报告（.md）**：简报 + 记录，吸收原来的"导出文档"和"导出标记"。
- **带证据的 PDF**。
- **会话（.md）**。

删去"导出摘要"：它要再花一次模型调用，内容和简报重复。表格 CSV 留在回答下方，因为它属于那条回答。

### 3.3 回答下方：7 个按钮 → 4 个

- 保留：复制 · 留存 · 重新生成 · 更多。
- "留存"合并了"留下这条"和"只留已核对的句子 (n)"，默认只留已核对的，次选项留整条。
- "用模型复核 (n 次调用)"移到合计行的"用 AI 复核"。
- 用量详情（首字延迟、每步 token 等十几行）只在设置里打开"显示用量详情"后出现，平时只显示一行文字。

### 3.4 设置：21 项 → 12 项以内

- "自动视觉预算"、"助手扫描上限"、"扫描缓存"合并为一项"云端识别：关 / 每次询问 / 最多 N 页"；清缓存（含 OCR 缓存）收进"高级"。
- 去掉识别语言选项：自动取"界面语言 + 英文"，现在默认值已经是这样。
- 去掉"PDF 清晰度"：保留自动。
- 去掉"默认跟随助手"：记住上次开关的状态即可。

### 3.5 其他

- 未扫描页的横幅、`scanUnindexed` 追问建议、命令面板里的"扫描全部未扫描页"是同一个动作的三个名字，只留横幅，叫"再读 N 页"。
- 空会话的示例问题从 5 条减到 3 条："总结前 N 页"和"总结第一页"语义重叠。
- 文档状态行有 7 种写法，减为 3 种："正在读取…" / "就绪" / "N 页读不出 · 读取"。识别置信度放进提示。
- 删除约 85–120 个没有用到的 i18n 键，并加一个检查脚本，发现未用的键时 CI 失败。
- 同一个 ⌘F 在两处各有含义（焦点在会话里时搜会话）。快捷键表里注明"焦点在会话中"，或者搜会话改用 ⌘⇧F。

### 3.6 用词表（每个概念一个词）

| 概念 | 中文 | English | 取代 |
|---|---|---|---|
| AI 帮手 | 助手 | Assistant | agent / 智能体 |
| 从页面图像取出文字（本机或云端） | 识别 | Read | 扫描 / 索引 / vision / OCR；"本机"、"云端"只作为补充说明 |
| 没有文字的页 | 读不出的页 | Unreadable page | 未扫描 / 稀疏页 |
| 助手留下的判断 | 结论 | Finding | 发现 |
| 读者划的重点 | 标记 | Mark | — |
| 机器对原文的核对 | 已核对 | Verified | — |
| 读者本人的确认 | 已确认 | Confirmed | "我检查过了"，容易和机器的"核对"混淆 |
| 保存一条结论 | 留存 | Keep | 留下这条 |
| 导出的报告 | 报告 | Report | 简报 / 摘要 |

## 4. 界面与交互

截图里看到的问题：

1. **提示遮住操作**：打开文档后，"已打开 xxx.pdf" 的提示压在会话面板右上角的收起和更多按钮上。改到左下角，或放进文档标题栏，2 秒后自动消失。
2. **欢迎页文案和状态矛盾**：AI 已连接（齿轮上是绿点），副标题仍写"先连接 AI"。按连接状态切换文案；按钮下方那句"用打开文档或拖入文件"和按钮本身重复，只留"或拖入文件"。
3. **每条提问下都常驻"编辑"**：改成悬停或聚焦时才出现，和回答下方的按钮一致。
4. **回答下方的图标没有文字**，对比度也低：常用的"复制"和"留存"带文字；其余收进"更多"。
5. **"读取第 1 页"和"已读页 1"重复**：同一信息显示了两次。合为一条，可以展开看读过的页。
6. **Chat / Record 标签太小**（约 11px，当前项只靠一块浅色底区分）。改成正常字号的分段控件，"记录"旁显示结论条数。
7. **空会话**：上方大片空白，建议问题挤在底部。建议改为紧贴输入框的 3 个选项；标题"Ready to ask"可以去掉。
8. **搜索框有两个关闭按钮**（框内 ×，框外 ×）；结果列表里命中词没有高亮；结果浮层遮住整页。只留一个关闭按钮，高亮命中词，浮层贴在工具栏下方、限高。
9. **标记栏空状态没有内边距**，文字贴着左边缘。
10. **命令面板打开时只显示"最近"一项**：输入为空时也应列出全部命令（按分组），否则无从发现。
11. **引文标记**是 0.68em 的上标方框，红色虚线和红色 2px 实线肉眼分不出。按 §3.1 改为三种状态，✓ ! ✗ 的字形本身就能区分，不依赖颜色（也照顾色弱读者）。
12. **页面上两种下划线**（读者的标记和助手的结论）样式接近，页边小竖条也不知道是什么意思。结论改用浅色底，标记保留下划线，页边竖条加上提示。

### 5.2 验收（全部可测）

- `npm run eval` 全绿；numbers 的写法变体组 0 误报，改数字的检出率仍 ≥85%。
- 每个缺陷有一条对应测试，修复前失败、修复后通过，测试名带上 B 编号。
- 新增 `scripts/ui-inventory.mjs`，在 CI 中用 DOM 数控件：回答下方可见按钮 ≤4；导出入口 1 个；设置项 ≤12；引文可见样式 3 种（外加灰色无状态）。
- i18n 检查：未使用的键 0，en 和 zh-CN 键集一致。
- `ui:shots` 重拍 12 张，§4 每条附前后对比，写进实施记录。
- B6 和 B7 各加一个故障注入测试：模拟写盘失败，再切换文档或语言，盘上数据不减。

### 5.3 不做

- 不加新的核对能力。多文档、语义级覆盖提示都留到 16.0 之后。
- 不删内部状态：`mismatch`、`unconfirmed` 等照常计算和导出，只改给读者看的那一层。
- 不重做视觉主题和配色，只改层级、字号、状态样式。

## 6. 风险

- **三种状态丢失细节**：细节全部保留在提示和记录里，导出的报告仍写具体原因；"请看原页"合并了四种原因，由提示区分。
- **删设置让高级用户不便**：保留"高级"折叠区；删掉的项在"关于"里写清改成了什么。
- **读 argv 冷启动**是新增的平台代码，需要在 macOS 和 Windows 真机上确认。和 OCR 耗时、Acrobat/Preview 显示效果一起，列入待你真机验证的项目。
- **`eval:live` 仍然缺 API key**：16.0 不依赖它，但简化后的提示词（状态词变了）最好能用真实模型跑一次。

### 7.2 与计划不同之处

- **`ui-inventory` 是浏览器脚本，不在 CI 里。**
  - 它和 `audit:*` 一样，需要开发服务器和 Playwright。
  - CI 里跑的是：各组件的 jsdom 测试（导出对话框、回答下方按钮、引文标记层级），以及 `check:i18n`。`check:i18n` 由 `prebuild` 调用，CI 的构建步骤会执行它。
  - 没有改 `.github/workflows/`。
- **设置实测 9 行（通用 6，AI 服务 3），计划是 ≤12。**
  - “PDF 清晰度”不再显示，改为自动；此前存下的偏好仍然生效。
  - 识别语言改为跟随界面语言，此前存下的选择不再生效。原因：界面上已无入口，旧选择会一直卡住。
- **报告 = 简报 + 标记，可选附上全文。**
  - 原来的“导出文档”（整份文档转 Markdown）没有直接删掉，改成报告里的一个勾选项。
  - 这样导出仍是 3 种，功能没有丢。
- **“扫描未读页”三处合一。**
  - 保留横幅；命令面板里的命令改用同一个名字。
  - 删掉的是追问建议：它其实是把“扫描 12 页”作为一个问题填进输入框，和“读取这些页”不是同一个动作。
- **§4 第 12 条（结论与标记在页面上样式接近）未改。**
