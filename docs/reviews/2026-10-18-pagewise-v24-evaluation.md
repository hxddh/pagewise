## 2. 基线为什么能在 CI 里录

| 条件 | 现状 | 依据 |
|---|---|---|
| 驱动真实 app 跑问题集 | `eval/live/run.mjs` 已就绪；不给 key 时跑脚本化模型，整条路径验证过 | 读代码，`eval/README.md` |
| OpenAI 兼容的 base URL | 支持 `PW_EVAL_BASE_URL`、`PW_EVAL_API_KEY`、`PW_EVAL_MODEL` | `run.mjs:38-40` |
| 不用你的 key 就能调模型 | GitHub Models：在 Actions 里用 `GITHUB_TOKEN`，权限加 `models: read` | 上游文档，**未在本仓库验证** |
| 从这个容器直接调 | 不行，models.github.ai 被代理拒绝（403） | 实测 |
| 免费额度 | 免费档对每次请求的输入 token 数和每天的调用次数都有上限。一次带工具定义和页面文本的请求会不会超，**未量** | 待第一次运行 |

两种可能的结果都有用：

- **跑通**：第一次得到真实分母，包括引文定位率、句子状态分布、每步的 `outputTokens`，提交到 `eval/baselines/`。
- **因额度失败**：失败本身就是一个数据点，说明一次请求有多大。之后改用你的 key，用同一个 workflow 跑，只需把 key 放进仓库 secret，不必交给我。
