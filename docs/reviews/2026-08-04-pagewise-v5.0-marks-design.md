# PageWise 5.0 设计：让读过的东西留下来

日期：2026-08-04 ｜ 基线：4.4.0（已发布）
依据：`2026-08-04-pagewise-next-major-review.md`（候选 B）
实测编号接续该文（V1–V33）。

前提不变：不考虑历史兼容；陈旧依赖直接删；**不新增依赖、不新增 Rust 命令、不引入新的架构层**。

---

## 0. 一句话

在页面上划一段，它就留在那儿——下次打开还在，导出带得走，模型看得见。

---

## 1. 只有一种东西：标记（mark）

不做"高亮"和"批注"两种类型。**一个标记 = 位置 + 当时的文字 + 可选的一句话。** 没写话的就是高亮，写了话的就是批注。一个类型、一个存储、一个图层、一个列表。

```ts
interface Mark {
  id: string;               // crypto.randomUUID()
  page: number;             // 1-based
  rects: PdfRect[];         // 通常 1–3 个，见 §3
  text: string;             // 创建时取到的原文快照
  note: string;             // 用户写的话，可为空
  createdAt: number;
  stamp: string;            // 创建时文件的 file_stamp
}
```

`PdfRect` 是现成的类型，`file_stamp_cmd` 是现成的命令。**没有新概念。**

### 为什么锚在几何上

复查里实测过：页文本与文本位置来自两条不同的提取路径，整句引文只有 24% 能定位（V33）。**文本锚点在这个产品里不可靠。** 而页码 + 页面比例矩形不经过任何提取路径，不受上游版本变化影响——我们刻意不固化 `pdf-inspector` 版本，这一点尤其重要。

`text` 快照不承担定位职责，只承担**降级**职责：文件被替换、矩形指错了地方时，用户至少还看得见自己当初标的是什么。这是 V33 教训的反向应用——不在需要正确的地方依赖文本匹配，但在可以降级的地方留文本兜底。

---

## 2. 存储：照抄 `index-store` 的形状

新文件 `src/lib/mark-store.ts`，`LazyStore("marks.json")`：

```jsonc
{ "version": 1, "docs": [ { "path": "…", "marks": [ … ] } ] }
```

三件事直接沿用 `index-store.ts` 已经写好并踩过坑的做法：

- **所有写操作串到一条 promise 链上**（`withStoreLock`）——那里的注释写得很清楚，未串行化的读-改-写会以 last-write-wins 丢数据。
- **合并写**（`FLUSH_DELAY_MS`）——连续划几段不该写盘几次。
- **容量上限**——每份文档 2,000 条、总计 20,000 条。一条标记约 400 字节，总量约 8 MB，正常使用永远碰不到；它只是防御，不是策略。

### 与索引缓存的一处关键差别

`index-store` 在 `stamp` 变化时**丢弃**缓存页——那是重新算一遍就有的东西。**标记不能这样处理，它是用户的劳动。**

文件变了就：**保留全部标记，把该文档标记为"基于旧版本"**，在列表和页面上给一个轻提示。矩形可能指错地方，但 `text` 快照还在，用户自己能判断。

同理，`docCache` 里"文档移出最近列表就清理聊天"那套逻辑**不适用于标记**。标记只受容量上限约束，不随最近列表淘汰。

## 3. 创建：选区已经在了，加一个按钮

`useAskSelection` 已经在跟踪选区，`PreviewPane` 已经在选区旁边浮出"询问这段"按钮。**同一个位置加第二个按钮"标记"。**

转换用现成的 `clientRectToPageRect`（4.1 修过旋转页，已测），文字快照用现成的 `selectionQuote`（它内部走 `extract_region`，还能带表格）。

**一处必要的小改动**：`useAskSelection` 今天只暴露选区的一个包围盒。跨三行的选区，包围盒会连第一行的左边距和第三行的右边距一起框进去，看上去是一大块。`Selection.getClientRects()` 原生就给按行的矩形，所以改成同时暴露 `rects: ClientRect[]`，用同一个函数循环转换即可。

一个字段、一个循环。换来的是高亮**看起来是对的**——这是可见缺陷与否的差别，值得。

---

## 4. 渲染：第三个覆盖层，和前两个一样

`src/features/preview/MarkLayer.tsx`，与 `SearchHighlight`、`LinkLayer` 并列放在 `preview-page-frame` 里，形状完全一致：拿 `path` / `page`，用 `pdfRectToBox` 转成比例框，绝对定位。缩放、DPR、窗口大小都不用管——4.1 选比例坐标就是为了这个。

点一个标记：弹出它的便签，可编辑、可删除。**没有第二种交互。**

---

## 5. 找得回来：侧栏加第三个标签

`OutlineSidebar` 已经接受 `tabs` 这个 ReactNode，今天是"页面 / 大纲"两个。加第三个"标记"，列表按页码排序，每条显示页码 + 快照首行 + 便签，点击跳页。

这是本版**唯一**的新 UI 面（除了那个按钮和那个图层）。没有标记列表的话，300 页的文档里划过的东西等于没划——这一项不能省。

---

## 6. 造好通往模型的路

4.3、4.4 两轮的教训是同一个：造了能力不造路等于没造。这一版对应三处，全部与 4.4 的 `links` 同构：

- **`document_outline`** 增加 `pagesWithMarks`，与 `pagesWithTables` / `pagesWithFigures` / `pagesWithLinks` 对称。
- **页读结果**（`read_pdf_page` / `read_pdf_range` / `read_section`）带上覆盖页面的标记：`{page, text, note}`。**与正文分开**，不进 ⌘F、不进搜索索引——和 4.4 对链接的处理是同一条界线。
- **系统提示**加一句：用户标出来的段落是他关心什么的最强信号，回答时优先照顾。

复用 4.4 刚写的 `withPageLinks` 的形状即可，连预算计费的写法都一样。

### 模型只读，不写

**不让 agent 创建或修改标记。** 那需要另一整套确认与撤销语义（写到用户的东西上，错了怎么撤、批量怎么办），而这一版的收益不依赖它。这条界线要写进工具描述里，避免模型尝试。

---

## 7. 带得走：导出

`documentToMarkdown`（现成）末尾追加一节"标记"，按页码列出快照与便签。导出是标记唯一的可移植出口——见 §8 为什么不写进 PDF。

---

## 8. 明确不做的

| | 理由 |
|---|---|
| **把标记写进 PDF 文件本身**（标准 PDF 注解） | 可移植到别的阅读器，确实诱人。但需要引入一个 PDF 写入依赖（`pdf-inspector` 只读），并且要**改写用户的原始文件**——写坏一份合同的代价远大于跨阅读器可见的收益。导出 Markdown 是这一版的可移植答案 |
| 颜色 / 标签 / 分类体系 | 先只有一种外观。分类是等到有人有几百条标记时才成立的问题，现在加就是猜 |
| 自由绘制、图形标注 | 不是"读"这件事的一部分，且要引入一套完全独立的输入与渲染 |
| 让 agent 自动标出重点 | §6：模型只读。而且"自动标重点"是把模型的判断伪装成用户的判断 |
| 跨设备同步 | 需要账号体系。PageWise 是本地产品 |
| 标记随文本重排自动重定位 | 正是 V33 否掉的那件事——76% 的失败率 |

建议 **5.0.0**。不是因为改动量——改动量不大——而是 PageWise 到今天为止是只读的：读、问、答，关掉之后文档上什么都没留下。允许在文档上留下东西，改变了这个产品是什么。

## 12. 实施记录（2026-08-04）

六项全部落地。§12 的两条待验证均已确认：

- **快照长度**：沿用 `MAX_QUOTE = 500`，2,000 条上限下最多约 1 MB，在 §2 的预算内。
- **跨页选区**：`useAskSelection` 检查 `anchorNode`/`focusNode` 都在单页文本层容器内，跨页选区今天就产生不了，无需处理。

### 落地时新增的三个决定

1. **`lineRects` 的两条边界**：忽略宽或高 ≤1px 的 client rect（浏览器在换行处会报这种塌缩矩形），并把矩形数截到 200。取不到任何按行矩形时退回包围盒——宁可画得糙，不可画不出来。
2. **批注卡片放在预览底部**，不做贴着标记的浮层。浮层要躲页面边缘、每次缩放重新定位，而且会盖住正在批注的那几个字。
3. **大纲标签改为禁用而非隐藏**。侧栏标签栏现在必须常显（否则够不到"标记"），于是没有大纲的文档若仍显示该标签，点了会静默退回"页面"。

### 与设计稿的一处偏离

设计稿 §2 说"文件变了给一个轻提示"，落地时做成了**两级**：侧栏列表顶部说"其中一些标记是在文件改动前做的"，选中单条时卡片再说"这一条创建于较早版本"。列表一级回答"要不要担心"，单条一级回答"担心哪一条"，两处都用真实数据，没有多余状态。

- **快照文字的长度上限**。`selectionQuote` 现在按 `MAX_QUOTE = 500` 截断，标记沿用即可，但要确认 500 字符的快照乘以 2,000 条仍在预算内（约 2 MB，在 §2 的上限之内）。
- **跨页选区**。`useAskSelection` 限制在单页的文本层里，所以跨页选区今天就不可能——落地时确认这条约束仍然成立，成立就不用处理。
