## 1. 区域标记

### 1.1 交互：工具栏上的一个开关

选中文字做标记的路子保留不动。新增一个**框选模式**：

- 预览工具栏一个按钮，点亮后进入框选；再点、或按 Esc 退出
- 模式内在页面上拖出一个框 → 立刻成为一条标记，并选中它（沿用 5.0 打开批注卡片的行为）
- 模式**保持开启**直到主动退出

考虑过并否掉的两种：

- **按住修饰键拖拽**：不占屏幕、不引入模式，但没有任何可见提示，等于只有知道的人能用。5.0 已经犯过一次"造了能力不造路"的错，不再犯第二次。
- **拖完一次自动退出**：读者在扫描件上标东西通常是连着标好几处，每次都要重新点开是折磨。

模式是可见的（按钮点亮），Esc 可退出，所以不存在"不知道自己在什么模式里"。

### 1.2 图层

新增 `RegionSelectLayer`，与 `MarkLayer` / `LinkLayer` 并列放在 `preview-page-frame` 里：

- 未开启时 `pointer-events: none`，对现有的选字、点链接、点标记零影响
- 开启时接管指针，画一个橡皮筋框；`pointerup` 时把屏幕矩形交给 `clientRectToPageRect`
- 小于 8×8 CSS 像素的拖拽当作误触丢弃——点一下不该产生一条看不见的标记

### 1.3 快照文字

用现成的 `extract_region(path, page, rect)`（顶左原点，正是 `clientRectToPageRect` 的输出，无需换算），它连表格都能给。

**但直接拿它的返回值当快照是错的**——实测（V35）：

```
scanned.pdf  extract_region → "[Image: X4]"
attn.pdf     extract_region → "[Image: I]"
paper.pdf    extract_region → "Einführung in die\nGeometrie und Topologi…"
```

扫描页返回的不是空串，是**占位符**。照单全收的话，读者框了一张图，侧栏里会显示 `[Image: X4]`，看上去像是"框住的文字"，实际是提取器的内部记号。

→ 规则：**只由 `[Image: …]` 构成的返回值一律当作空快照。** 有表格就用表格（`region.table`），否则用剥掉占位符后的正文，全空就是空。

5.0 的选区引用没有这个问题——`selectionQuote` 只在返回值是表格时才采用它，其余情况保留用户实际选中的 DOM 文本。区域标记没有 DOM 文本可退，所以这条规则是这一版新增的。

**扫描页上快照为空——这是可接受的结果，不是失败。** 5.0 已经定了界线：几何是锚点，文字只是给人看的兜底。区域标记在扫描页上退化成"位置 + 你写的话"，这比"完全不能标"好得多。空快照的标记在侧栏显示为 `（无文字）`（`marks.noText` 已有）。

### 1.4 数据：加一个字段，不加一个类型

```ts
interface Mark {
  …
  /** "text"（默认）或 "region"。只影响画法，不影响定位。 */
  kind?: "text" | "region";
}
```

为什么值得加：**两者的正确画法不同**。文字标记是行上的黄色底纹；区域标记若也铺一层底纹，会把它框住的那张照片/图表盖住——而看清楚被框住的东西正是框它的目的。所以区域标记画成**描边框**，不填充。

这不违反 5.0 的"只有一个类型"：仍然只有一个 `Mark`、一个存储、一个图层、一个列表。`kind` 是渲染提示，不是第二种实体，也不参与定位。旧标记没有这个字段，按 `"text"` 处理。

## 2. `document_outline` 直接给出标记

现状：只报 `pagesWithMarks`（压缩页码区间）。模型要看内容就得去读那些页——20 个标记散在 20 页上就是 20 次页读，而这些文本本来就在内存里、总共几 KB。

改成把标记本身带上：

```jsonc
"marks": [{ "page": 12, "text": "…", "note": "对不上第 3 页" }],
"marksNote": "Passages the user marked. Read-only."
```

- 上限 **100 条**，每条快照截到 **120 字符**（列表是用来定位的，要全文就去读那一页）
- 超过上限时给出 `markCount` 与 `pagesWithMarks`，让模型自己决定读哪几页
- 按现有写法计入预算

复用 `withPageMarks` 的形状，与 4.4 的 `links` 完全同构。

## 3. 侧栏过滤框

标记侧栏顶部加一个输入框，按 `text` + `note` 过滤（大小写不敏感，NFC 归一，与文档搜索同一套归一方式）。

**不把批注并进 ⌘F 文档搜索。** 文档搜索回答的是"这份文档里有什么"，混入用户自己写的话会让命中结果的来源变得含糊——与 4.3 拒绝把页眉留在正文、4.4 拒绝把链接塞进正文是同一条判据。

---

## 4. 单独导出标记

命令面板加一项"导出标记"，与现有的"导出文档 / 导出对话 / 导出摘要"并列。

`export-document.ts` 里的 `marksSection` 已经写好，抽成 `marksToMarkdown(doc)`（带文档标题抬头），`SessionProvider` 里照抄 `exportDocument` 那 12 行，文件名 `<文档名>-marks.md`。

没有标记时命令不可用，而不是导出一个空文件。

## 7. 明确不做的

| | 理由 |
|---|---|
| 陈旧标记"一键消除提示" | 那句提示陈述的是事实。允许清掉只是把一句真话藏起来 |
| 标记随文本重排自动重定位 | V33 的 76% 失败率 |
| 图片文档的标记 | 没有页面几何这一层，`extract_region` 也不适用 |
| 批注并入文档搜索 | §3 |
| 颜色 / 标签 | 5.0 已否：等有人攒到几百条才成立的问题 |
| 让模型创建标记 | 5.0 已否：需要另一套确认与撤销语义 |
