# v23 评估：先有一个读者

*2026-10-15。基线 main `a0edb7c`（`VERSION 21.1.1`）。*

*口径沿用 v21、v22 两稿：**实测**＝在这个容器里量出来或复现出来的；**读代码**＝`file:line`；**上游**＝GitHub API 读到的；**未量**＝没量。*

## 0. 结论

1. **21.1 带出了一个高、三个中等的缺陷，应该先发 21.1.2 修掉，不等 v23。** 最重的一条：一份扫描件只要有一页（封面、空白页）在切换到中英双语之前就已按英文写进缓存，下次打开时这次切换就被忘掉，整份扫描件每次打开都重新 OCR 一遍。CHANGELOG 写的「选择随 OCR 缓存记住」在这种常见情况下不成立。另一条是回归：21.1.0 的视觉判断把 Ollama 上真能看图的 `qwen3-vl`、`mistral-small3.1` 当成纯文本模型拦下了。详见 §1。
2. **产品信号仍然是零，而且现在量清楚了。** 上游：**101 个发布，安装包合计下载 76 次**，平均每个发布 0.75 次；0 star、0 fork、0 个 issue。仅 10 月 14–15 日两天就发了 v17.0.0 到 v21.1.1 共 11 个版本。没有自动更新，macOS 上每装一个新版本都要再跑一次 `xattr`。真实模型基线仍不存在。
3. **v22 的「不做」清单里写着：在有基线之前，不写 v23 方向评估。** 这份评估没有违反它：它不提新的阅读功能，只回答一个问题——**为什么 22 个大版本之后还没有一个外部读者，v23 能做什么去改变这件事**。
4. **建议**：v23 的主题是「先有一个读者」。必做三件：自动更新、降低发布频率、留一条反馈通道（§3.2）。基线仍然是前提，但它卡在你提供 key，不卡在代码（§3.3）。新的阅读功能一律推迟到有了基线或第一条外部反馈之后。

- 没有重渲染风暴；
- `cargo test` 60/60 通过。

## 2. 为什么还没有读者

### 2.1 数字（上游）

- **下载**：101 个发布，合计 76 次，按月是 7 月 23 次、8 月 14 次、9 月 27 次、10 月 12 次。8 月以来 76 个发布、53 次下载。没有 traffic 数据：这个环境的 token 读不到 views/clones。
- **社区**：0 star、0 fork、0 watcher；open issue 计数是 2，都是 7 月的草稿 PR，不是读者提的。
- **节奏**：tag 共 108 个。10 月 14–15 日发了 11 个版本（v17.0.0 到 v21.1.1），main 上这两天共 30 个提交。

下载量这么低，基本可以排除「有人用、但没人反馈」：大概率是作者自己在下载。

### 2.2 一个新读者要过的门（读代码 + 实测）

1. **找到它**：0 star，没有任何入口。README 是开发者视角，`## Install` 在第 98 行，前面是构建说明。
2. **装上它**：macOS 要在终端执行 `xattr -dr com.apple.quarantine /Applications/PageWise.app`，而且每个新版本都要再执行一次（ad-hoc 签名每次构建都不同，README:110-120）。Windows 要点「更多信息 → 仍要运行」。
3. **下载量**：Linux 的 AppImage 有 95 MB，是 `.deb`（17 MB）的 5.5 倍。**实测原因**：AppImage 把整套 WebKitGTK 打了进去，解包后 270 MB，其中：
   - `libwebkit2gtk` 86 MB，`libjavascriptcoregtk` 33 MB，`libicudata` 29 MB；
   - `librsvg-2.so` 以三个完全相同的 11 MB 文件出现，不是符号链接（已逐字节比较）。

   `.deb` 用系统自带的 WebKit，所以小。95 MB 基本是 Tauri AppImage 的固有成本。librsvg 的重复后来量过（见 §3.2 第 5 条），不占下载体积。
4. **用起来**：欢迎页写着「先连接 AI，再打开文档」。不给 key 也能读、能搜、能本地 OCR，但这件事页面上没说。
5. **保持更新**：**没有自动更新**（`Cargo.toml` 和 `tauri.conf.json` 里都没有 updater）。按现在的节奏，装上的人一天之内就落后五个版本，而每升一次级，macOS 上都要重新下载、再执行一次 `xattr`。
6. **说出问题**：应用里没有任何反馈入口（`git grep "issues/new"` 无结果）。

前三道门里，公证需要开发者账号，那是你的事。其余几道都不需要外部资源。

## 3. v23 的范围

### 3.1 先发：21.1.2（不等 v23）

§1 的第 1–5 条，外加第 7、10 条：

1. **重开时记住双语选择**：
   - 切换时把文档已读的英文页标记为待重读，不带进双语分区（同时修第 2 条）；
   - `restoreOcr` 遇到两个分区都有内容时，按页数和可信度比较，不再只要英文非空就选英文；
   - 「全是短页」时 `meanConfidence` 不再返回 100。
   - 验收：评审者的两个复现测试反过来断言，并在 OCR eval 里加一个「封面 + 中文正文」的重开场景。
2. **视觉判断不误伤**：家族前缀匹配之前先看名字里是否带 vision 标记（已有的 `looksLikeVisionModel`）；`qwen3-vl`、`mistral-small3.x` 加进表里。验收：对 Ollama 常见视觉模型逐个断言 `canSeeWith`。
3. **回答下方那一行跟着重新核对**：`tally` 和 `reviewable` 订阅 `checksEpoch`。
4. **带标注的 PDF 也走排他临时文件**：先写进 `store_io` 的临时文件再提交；保存失败时删掉临时文件。
5. **临时文件名不超长**：后缀缩短；最终文件名太长时退回较短的唯一后缀。启动时清理 app 数据目录里属于本进程以外的 `.pagewise-tmp`。
6. 修正四处过时注释。

第 6、9 条（CSV 级别、导出前的等待）放进 v23，不阻塞补丁。

### 3.2 必做：v23「先有一个读者」

1. **自动更新**（`tauri-plugin-updater`，发布时附带 `latest.json` 和签名）：
   - 读者从此不再停在第一天装的版本上。
   - macOS 上，更新器下载的文件不经浏览器，不带隔离属性，有可能连每个版本一次的 `xattr` 也省掉。这一点需要真机验证，**未量**。
   - 需要你做一件事：在本地生成更新签名密钥，把私钥放进 GitHub secrets。
   - 验收：从 v23 升到 v23.0.1 的端到端测试（Linux 在 CI 里跑，macOS 和 Windows 真机验证）。
2. **发布节奏**：
   - 在 `RELEASE.md` 写明：补丁随修随发；功能合并到 main 后攒成一个版本，**至少一周一次、最多一周一次**；大版本号只给不兼容的改动。
   - 同时在 `CHANGELOG.md` 顶部说明 v20–v22 的编号沿革：v22 以 21.1.x 发布。
   - 这一条只改文档和习惯，不改代码，但没有它，第 1 条的更新器会把一天五个版本推给读者。
3. **反馈通道**：
   - 设置页和命令面板各加一个「报告问题」，打开预填好的 GitHub issue，只带版本号、平台和界面语言，不带文档内容，不加遥测。
   - 再加一个 issue 模板。
   - 验收：组件测试断言链接里不含任何文档路径或文件名。
4. **首屏说清楚不给 key 能做什么**：欢迎页加一句「不连 AI 也能阅读、搜索和本地 OCR」。只改文案，不加设置。
5. ~~AppImage 去重~~：**实测后不做。** 把解包后的目录按原样和去重后各压一次 squashfs（zstd，块大小与发布包相同），两次都是 94,228,480 字节：squashfs 本身就会合并内容相同的文件，三份 librsvg 在下载包里只占一份。

### 3.3 必做但卡在你：真实模型基线

脚本已经就绪：`eval/live/run.mjs`，不给 key 时会跑脚本化模型，整条路径已经验证过。缺的只有 key。

给一个 key（例如 DeepSeek 或 gpt-4o-mini），我按 `eval/README.md` 的流程跑 `contract-zh,paper-en`，前 10 题录一份提交到 `eval/baselines/`。它会第一次给出：

- 真实模型的引文定位率；
- 句子状态的分布；
- 每步的 `outputTokens`。

**v24 的方向评估以这份基线为输入，而不是以代码审查为输入。**

### 3.4 不做

沿用 v21、v22 的「不做」清单。新增两条：

- **v23 不加新的阅读功能。** 已知可做的改进（大纲窗口化、BM25 增量更新、每页 `getPageGeometry` 缓存）都已经量过，都在预算内（21.1.1），没有理由现在做。
- **不加遥测。** 反馈只走读者主动点的链接。

### 3.5 版本号

21.1.2 是补丁。v23 加了自动更新，但不改变存储格式或已有行为，按 SemVer 应发 **21.2.0**。如果你更希望版本号和代号对齐（v23 → 23.0.0），请明确告诉我，我会在 CHANGELOG 里写明这次大版本号不代表不兼容。

**决定（2026-10-15）**：按每轮一个大版本发布，v23 发 **23.0.0**。v22 已经以 21.1.x 发出，不再补发 22.0.0。`docs/RELEASE.md` 和 `CHANGELOG.md` 顶部的说明已按此改写。

### 3.6 需要你提供的

- **模型 key**：做基线（§3.3）。
- **更新签名私钥**：放进 GitHub secrets（§3.2 第 1 条）。我可以写好生成步骤，私钥不经过我。
- **Apple 开发者账号**：做公证。
- **真机**：macOS 和 Windows，验证更新器、对话框、拖放、Finder 冷启动和页码。
