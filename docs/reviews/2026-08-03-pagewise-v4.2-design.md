日期：2026-08-03 ｜ 基线：4.1.0（已发布）

## 0. 先更正一条我自己写错的数据

4.1 的设计文档与 PR 描述里我写过：

> 23,107 个文本 item 里**几何缺失的是 0 个**。

**这个数字是错的。** 那次测量实际跑在 `cjk.pdf`（12 个 item）上，`paper.pdf` 的输出被我当时的 `sed` 过滤截掉了，我却把它当成 23,107 的结论写了出来。本轮逐样本重测：

| 样本 | 文本 item | 零宽 | 零高 |
|---|---|---|---|
| `paper.pdf` | 23,107 | **75** | 0 |
| `cjk.pdf` | 12 | 0 | 0 |
| `rich.pdf` | 7 | 0 | 0 |
| `form.pdf`（本轮自造） | 1 | 1 | 0 |
| `s1.pdf` | 7 | 0 | 0 |

零宽 item 占 `paper.pdf` 的 0.3%。它的后果是**画出一个看不见的高亮框**——搜索命中落在这类 item 上时，用户会以为高亮失效了。这不是假想缺陷，是真实文档里存在的情况（§1.3）。

## 1. 前两轮的遗漏（本轮审计发现）

### 1.1 产出了却没人消费的模型字段

```
pdfType      前端引用 1 处 —— 就是 load-document.ts 里那次赋值，无任何读取
confidence   根本没进 LoadedDocument —— 跨 IPC 传过来后直接丢弃
```

两者在 Rust 内部都有用（`confidence ≥ 0.9` 驱动扫描件短路），但**不需要跨 IPC**。

处置：从序列化模型里移除，Rust 内部照常使用。这不是砍能力，是删无人读取的负载。

> 顺带重新评估 4.0 落地顺序里那条从未实现的"**扫描件成本预告**"（打开即告知"本文档 N 页需视觉索引"）。审计后判定：**与 3.6.1 已有的能力重复**——聊天面板已经收到 `unscannedPages` 并给出一键扫描入口，而扫描件在 4.0 之后每页都是空的，那个计数本来就等于全部页数。为它再造一处提示只是重复。**不做。**

### 1.2 不可达的折叠导轨分支

`ThumbnailSidebar` 的 `collapsed` 属性只有一个调用方，恒为 `false`：

```
PreviewPane.tsx:367   collapsed={false}
```

于是 `if (collapsed)` 的整个折叠导轨分支（含 `preview.thumbnailsShow` 文案）**永远不会渲染**。

处置：删掉属性、分支与只被它使用的文案。侧栏的显隐由 `thumbsVisible` 在 `PreviewPane` 里管，本就不需要组件内再有一套。

### 1.3 零宽 item 产生看不见的高亮框

见 §0。处置：`page_text_items` 在 Rust 侧就跳过零宽/零高的 item——一个没有面积的框，无论对搜索高亮还是将来的任何叠加层都没有意义，不该让每个消费方各自去防。

## 2. 已验证不需要新建的（表单字段）

`ItemType::FormField` 一直没实测过，本轮补上。自造一份填好的 AcroForm PDF（两个文本域，1551 字节，手写对象表）：

```
items=3  text=1  image=0  link=0  formfield=2
  "applicant_name: Ada Lovelace"  type=FormField  x=72 y=700 w=300 h=24
  "amount: 1,284.00"              type=FormField  x=72 y=650 w=200 h=24

### markdown
## Grant application

applicant_name: Ada Lovelace

amount: 1,284.00
```

**表单值已经通过 4.0 的 markdown 文本路径完整进入文档**——agent 现在就能读到"申请人是 Ada Lovelace、金额是 1,284.00"。

→ 不需要任何新功能。把 `form.pdf` 收作夹具，锁住这个行为不被上游漂移掉，就是全部要做的事。

---

## 3. 唯一的新能力：`read_section`

4.1 给了 agent 一棵真实的章节树，但它**读文档的方式还停留在页**：拿到大纲后仍要自己把"2.3 单纯复形"换算成页码区间，再调 `read_pdf_range` 猜边界。猜错了要么漏内容，要么把下一节也读进来。

新工具：

```
read_section(title | index) → { title, startPage, endPage, text }
```

边界从大纲直接得出：本条目的页到下一条目的页。零新增解析、零新增命令——`outline` 和逐页文本都已在 `docCache` 里。

价值：agent 从"按页翻找"变成"按结构取用"。对"总结第三章"这类问题，从多次试探性 range 读变成一次确定的读取。

约束（如实写在工具描述里）：**节的边界来自合成大纲**，对没有书签又标题字体不明显的文档可能不准；此时 `read_pdf_range` 仍是兜底。

---

## 4. 不做什么

除 §1.1 的扫描预告外，4.1 已经用证据排除的四项**结论不变**，本轮无新证据推翻：结构化表格（需 TSR 模型；矢量网格漏真表造假表）、标记结构树（够不着 lopdf）、`MarkdownProfile::Compact`（省 0.0%）、自建文本层（换不来什么）。

另外两项本轮考虑后放弃：

- **多栏检测暴露给 agent** —— `has_columns` 在 4.0 就因"不使用任何页号列表"的原则被丢弃。重新引入需要页号列表，而它能带来的只是"这页是双栏"这条 agent 用不上的元信息。
- **`is_bold` / `font_size` 用于改进大纲** —— 现有大纲的 L1 已经与书本目录逐条命中（V12），噪音集中在 L2 且已被规则过滤。没有可测的问题要解决。
