# 19.0 方向评估（重做）：减法

*2026-10-14。基线 18.0.0（main `9ef7d38`，tag `v18.0.0`，三平台产物已发布）。*

*来源标注：**实测**（在这个 orb 里量出来的）、**读代码**（文件:行）、**上游资料**。§0 结论，§1 现状（复杂度账），§2 19.0 提案，§3 包，§4 验收，§5 候选对比，§6 风险，§7 依赖，§8 核验记录。*

*这一版是**重做**。上一稿（同一天早些时候，未提交）把 19.0 写成了"书房"——多文档、跨文档提问、库级搜索、金额、缓存命中解析、首屏包。方向是错的：那是**膨胀**，不是质变。本稿按四条约束重写：**1 专注与简单；2 结构还债可以做；3 阅读面可以做；4 金额、缓存命中、首屏包要么给出理由，要么撤掉。** 答案在 §2.5：三项全部撤掉，理由逐条写明。*

## 0. 结论

1. **撤掉多文档（上一稿的支点 A）。** 它让产品变大：文档标签、跨文档运行时、库级搜索、分屏、每份文档并行的状态，每一项都要读者多理解一点。读者的真实动作是"读这一份、问这一份"，而这件事 18.0 之后已经顶级。**19.0 不加能力，减东西。**

2. **撤掉金额。** 理由：成本可见已经由用量行完成（页数/步数/token/缓存命中/扫描次数）；价格表会过期、要维护、把"用量"变成"账单"，而它不改变读者的任何决定。**为一行数字引入一张会腐烂的表，是膨胀的教科书例子。**

3. **撤掉 DeepSeek 缓存命中解析。** 理由：为一家提供商解析原始响应体（`prompt_cache_hit_tokens`），只为让一行里多一个数字；SDK 报 `cachedInputTokens` 的地方照旧显示。**为细节而细节。**

4. **撤掉首屏包改动。** 理由：启动实测 **237ms** 且已有门（预算 800ms）；把 `ai` 包移出 preload 是一个构建层改动（聊天路径改延迟加载），换来的差异在本地磁盘上不可感知。**已测量、无需动**——这一条留在 §1.7 的"不要动"里。

5. **保留结构还债（支点 B，用户已批准）。** 它不只是还债，它是**减法的前提**：934 行 / 35 prop 的 `ChatPanel`、30 字段只有 1 个消费者的 context、19 个返回值的 hook、11 个模块缓存加手写拆除清单——这些东西让"删掉一个面"变成三处改动。

6. **保留阅读面（支点 C，用户已批准），但重新框定。** 页边**不是新功能，它是标记本来的位置**——正因为标记回到纸面，侧栏才能从三个 tab 减到两个。动效是"界面不跳"，OCR 感知是"等待里能继续读"，两者都是让已有的东西变好，不是加东西。

7. **现在的复杂度是可以量出来的（实测）**：**18 个面**（读者能看到并与之交互的独立面板或浮层：rail、工具条、页面侧栏、面板 header、Chat、Record、dock、命令面板、文档搜索、会话搜索、设置、导出、库、欢迎页、页边注、选中浮层、Zen 层、追问行；短暂状态提示不计）、**14 条命令**、**同一件事最多 7 个入口**（打开文档）、**8 个 tab**（侧栏 3 + 面板 2 + 设置 3）、**扫描一件事 4 个旋钮**（脚本口径：设置两项 + 命令 + 横幅）、**483 个文案键**（脚本口径：en 目录递归计数）、CSS **6,005 行**、非测试源码 **37,680 行**。

8. **减法清单（7 项，都有证据）**：标记从侧栏移到页边（少 1 个面 + 1 个 tab）；会话搜索并入文档搜索（少 1 个面，一次 ⌘F 搜"你正看着的东西"）；追问行删除（答案下面少一行猜测）；两条 header 合成一条（9 个控件 → ≤6）；扫描旋钮 5 → 2（Off / Auto / All + 上下文里的横幅动作）；设置行 9 → 6（缓存行与截图开关进 Advanced）；命令 14 → 12（scan-all 与 follow 折叠）。见 §2.2。

9. **目标数字（可验收）**：面 **18 → 15**（会话搜索、追问行、面板 header 三处不再作为独立面）；tab **8 → 7**（侧栏 3 → 2）；命令 **14 → 12**；设置行 **6 → 5**（脚本口径）；扫描旋钮 **4 → 2**；文案键 **483 → ≤440**；CSS **6,005 → ≤5,600**；源码净减（不设硬指标，但要**下降**——这是"减法"这个词的诚实条件）。

10. **一句话的 19.0**：*更少的东西，做得更深。* 打开应用，界面里的面更少、每个动作只有一个主入口；标记回到纸面；答案下面不再有猜你想问什么；扫描件在后台一页页读，而你可以立刻读、立刻滚。结构上，那些"靠清单与约定"的东西换成"靠作用域与类型"。

11. **不减的三样（护城河）**：证据链（引文核对 + 三种状态 + 记录 + 导出）、性能与门、排印与沉浸（17.0–18.0 的成果）。**减法的判据只有一条：删掉它，读者少理解一点而能力不变。**

12. **依赖：19.0 不需要任何新依赖。** 这是"专注"最直接的证明——上一稿要的（价格表、新解析、构建改动）全部撤掉，剩下的工作都用已装的东西做（`radix-ui`、`motion`、React Compiler、`pdfjs-dist`、`tesseract.js`）。

## 2. 19.0：更少的东西，做得更深

### 2.1 目标句（验收单位）

> 打开应用，界面里的面比上一版少：侧栏只剩两个 tab，标记回到纸面；答案下面没有第三处"猜你想问"；⌘F 只在一处，搜的是"你正看着的东西"（文档与当前会话两段结果）；工具条只有一条，控件不超过六个；扫描只有两个旋钮。每一个动作都只有一个主入口，其余入口在命令面板里——而面板里的命令比上一版少两条。扫描件在后台一页页读，队列告诉我读到第几页，而我可以立刻读、立刻滚。

### 2.2 支点 A · 减法清单（7 项，每项带证据与净效果）

| # | 删/合 | 证据 | 净效果 |
|---|---|---|---|
| A1 | **标记侧栏 → 页边**（支点 C 的页边就是它的新家） | `MarkSidebar` 156 行 + `sidebar-tabs.ts` 的三个 tab | 侧栏 3 → 2 个 tab；少 1 个面；标记回到它属于的地方（纸面） |
| A2 | **会话搜索并入文档搜索** | `ConversationSearchBar` 76 行 + `useConversationKeys` 的搜索分支；两个 ⌘F 语义 | 搜索面 2 → 1；一个输入、两段结果（本文档 / 本会话）；`Alt+↑/↓` 会话导航保留 |
| A3 | **追问行删除** | `follow-ups` 块 + `lib/follow-ups.ts` + 6 个文案键 | 答案下面少一行；"问什么"只剩两处：输入框与选中浮层 |
| A4 | **两条 header 合成一条** | `PreviewToolbar` 232 行 + `.panel-header`；9 个控件分两行 | 一条 ≤6 个常驻控件（文件名、位置、面板 tab、溢出菜单） |
| A5 | **扫描旋钮 5 → 2** | 设置·本地 OCR + 云端页数四档 + scan-all 命令 + 横幅 + 每题上限 | 设置里两行：`本地 OCR` 开关、`云端页数` 三档（Off / Auto / All）；`All` = 现在的 scan-all（带确认），命令面板条目删除；横幅动作保留（上下文里的补救） |
| A6 | **设置行 6 → 5**（脚本口径：toggle 行 + pill 行） | 主题、语言、文字档、OCR、云端页数、截图开关、用量开关；另有缓存行与模型行（不计入该口径） | 缓存行与"附当前页截图"进 Advanced（一个是维护动作，一个是专家开关）；其余留在三组里 |
| A7 | **命令 14 → 12** | `useAppCommands.ts` 的 14 条 | 删 `scan-all`（并入 A5）、`toggle-follow`（进设置·阅读一行） |

**判据**：每一项都满足"删掉它，读者少理解一点而能力不变"。A1/A2/A3 是面与概念的减少；A4/A5/A6/A7 是入口与旋钮的收敛。

### 2.3 支点 B · 结构还债（减法的前提）

1. **消息层**：`ChatPanel` → `MessageList` / `MessageRow` / `Composer`，`ChatPanel` ≤250 行、props ≤12。**这一项直接服务于 A3/A4**：删掉追问行、合并 header 都要在这个 934 行的文件里动刀。
2. **会话层**：30 字段 context 删除，改成 App 直接调用的 workbench hook，返回值分三组（≤20 字段）。
3. **agent 层**：`useDocAgent` 19 个返回值收成 3 组（≤8）。
4. **文档作用域**：11 个模块缓存收进 `DocumentScope`（create/dispose），手写拆除清单删除；补一条"A 的文字不出现在 B"的回归测试（这一 bug 类被记录过三次）。

### 2.4 支点 C · 阅读面（不是加功能）

1. **页边**：标记（黄）、结论（紫）、引用本页的答案（indigo）在页面外缘成点；悬停出注、点击/Enter 跳转；**零布局位移**。它是 A1 的落点——标记从"侧栏里的一个列表"变成"纸面上的东西"。
2. **动效四处**：面板开合、答案插入（FLIP）、列表增删、页边出现；reduced-motion 全部瞬时；验收含"插入过程中无 >50ms 长任务"。
3. **OCR 感知**：可见队列（"正在读第 3 页 / 共 12 页"，可取消）；光栅与 OCR 解耦（页面立刻可读可滚）；识别进行中滚动扫描页 p95 ≤25ms。

### 2.5 支点 D · 三个"为什么"的回答

| 上一稿的项 | 决定 | 理由 |
|---|---|---|
| **金额**（价格表 + 估算） | **撤** | 成本可见已由用量行完成；价格表会过期、要维护、把"用量"变成"账单"；它不改变读者的任何决定 |
| **DeepSeek 缓存命中解析** | **撤** | 为一家提供商解析原始响应体，只为一行里多一个数字；SDK 报 `cachedInputTokens` 的地方照旧 |
| **首屏包（`ai` 移出 preload）** | **撤** | 启动 237ms 且预算 800ms；改动在本地磁盘上不可感知。留在 §1.7"不要动" |
| 高对比 / 强制色彩 | **保留** | 不是模式、不是新面：两套 token，让现有界面对低视力读者可用。今天全仓 0 处支持——这是缺陷，不是缺功能 |
| 键盘完整性 | **保留** | 同上：让已有的控件可达，不新增控件 |

**这一节的意义**：上一稿的四项"顶级细节"里，三项被撤、两项被重新归类为"把已有的东西做对"。19.0 不引入任何新的显示概念（没有金额、没有缓存解析、没有新开关）。

### 2.6 为什么这是质变

- **读者能感觉到的**：面更少、入口更少、答案下面更安静、标记回到纸面、扫描件能边读边等。这是"专注"在界面上的样子。
- **工程上的**：结构债还清之后，删一个面是三处改动变一处；"没有需要人记住的隐性约定"是顶级工程的定义，而它也正是减法的必要条件。
- **与 18.0 的关系**：18.0 让每个面变好；19.0 让面的数量变少。**同一件产品的两个方向，缺一个都不成立。**

## 4. 验收（全是计数与截图）

**减法**
1. 面 **18 → 15**（`ConversationSearchBar`、追问行、面板 header 三处不再作为独立面存在；`MarkSidebar` 作为面保留在侧栏里但少一个 tab——见第 2 条；计数脚本在 CI 里跑）。
2. 侧栏 tab **3 → 2**；面板 tab 2（不变）；设置 tab 3（不变）。

## 5. 候选对比

**减法 vs 加能力**

| 方案 | 判断 |
|---|---|
| A · 减法（**建议**） | 用户明确要求专注与简单；18.0 之后每个面已经够好，缺的是面的数量 |
| B · 多文档"书房"（上一稿） | 撤：它让产品变大；读者的真实动作是"读这一份、问这一份" |
| C · 只做结构债、不做减法 | 不足：结构债还清之后如果不减面，读者看不到任何变化（而债正是为了让减面变便宜） |

**搜索合一的两条路**

| 方案 | 判断 |
|---|---|
| A · 一个输入、两段结果（**建议**） | "⌘F 搜你正看着的东西"一句话能讲完；组件少一个 |
| B · 保留两个搜索、统一快捷键语义 | 拒绝：语义仍要解释"焦点在哪"，而且面没少 |

**扫描旋钮的两种收敛**

| 方案 | 判断 |
|---|---|
| A · 开关 + 三档（Off/Auto/All）（**建议**） | 三档覆盖三种意图（不读/后台读/全读），`All` 吃掉 scan-all 命令 |
| B · 只留一个开关（全自动） | 拒绝：全读是有成本的动作，必须由读者决定 |

**页边的形态**

| 方案 | 判断 |
|---|---|
| A · 页面外缘的点（**建议**） | 零布局位移、不遮挡纸面、能承载三类东西；它是标记侧栏的替代 |
| B · 页面内浮层（选区旁） | 拒绝：已有选中浮层；再叠一层会遮纸面 |

## 6. 风险

- **减法会误删有用的东西**：每一项都要在包里单独可回退（一次一项、每项跑 `ui:shots`/`ui:inventory`/`npm test`）。判据只有一条：删掉它，读者少理解一点而能力不变——不满足就不删。
- **页边是 A1 的落点**：先做页边、再删标记侧栏；顺序反了会有一段时间"标记无处可看"。
- **搜索合一要保住 `Alt+↑/↓`**：会话导航是键盘用户的主要手段，不能被合并带走。
- **`ChatPanel` 拆分面积大**（934 行 / 35 prop / 流式细节）：一次一条路径；`useChat` 保留。
- **`DocumentScope` 会暴露隐式依赖**（某些模块 import 时就建缓存）：先"注册 + 断言"，再逐个搬。
- **高对比与键盘是横向工作**：验收是截图 + focus 断言，不是"加了 CSS"。
