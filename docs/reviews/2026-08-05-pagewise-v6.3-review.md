# 6.3 评估：六个不存在的变量、一批已经写歪的标记，以及一套只存在于纸面上的设计系统

日期：2026-08-05 ｜ 基线：6.2.0（已发布）
实测编号接续 `2026-08-04-pagewise-v6.2-review.md`（V1–V55）。

---

## 0. 结论

你这次点了三件事：**功能完善、修 bug、界面现代化和优雅**。我按这三条各挖了一轮，结果是第二和第三条其实是同一件事——

**界面上真正的丑，不是审美问题，是 CSS 里有六个变量根本不存在。** 其中两处会直接产生可见故障：浅色主题下"标记"按钮的字是白的（背景 `#f4f4f5`，看不见）；标记备注输入框没有背景色。这些不是"再调调间距"能解决的，是坏了。

然后是那套设计系统：`tokens.css` 定义了 4 个字号 token，CSS 里 **193 处直接写 px、只有 13 处用 token**；圆角 token 有 2 个，实际用了 **10 种不同的值**。系统在纸面上存在，代码里不存在。

外加 6.2 的一个尾巴：**它止住了产生越界标记，但没有修已经写进文件的那些**。

## 1. 六个不存在的 CSS 变量 · V56

```
undefined custom properties used in CSS:
  --bg              used 1x   fallback=no
  --bg-primary      used 1x   fallback=no
  --text-primary    used 6x   fallback=部分
  --radius-sm       used 2x   fallback=部分
  --text-tertiary   used 1x   fallback=yes
  --total-scale-factor  used 1x  fallback=yes（pdf.js 自己注入，正常）
```

没有 fallback 的 `var(--不存在)` 在计算值阶段无效，属性退回 `unset`——对 `color` 是继承，对 `background` 是透明。所以：

### 1.1 浅色主题下"标记"按钮的文字是白的（最严重）

```css
.mark-selection-btn {
  background: var(--bg-elevated, #2c2c2e);
  color: var(--text-primary, #fff);   /* --text-primary 不存在 → 落到 #fff */
}
```

`--bg-elevated` 在浅色主题里是 `#f4f4f5`。**白字压在近白底上**：选中文字后弹出的"标记"按钮，浅色主题下等于一个空白方块。

### 1.2 标记备注输入框没有背景

```css
.mark-note-input {
  background: var(--bg-primary);   /* 不存在，无 fallback → 透明 */
  color: var(--text-primary);      /* 不存在，无 fallback → 继承 */
}
```

写备注是标记功能的一半，而这个输入框是透明的，直接透出后面的东西。

### 1.3 编辑已发送消息的输入框同样没有背景

```css
.message-edit-input { background: var(--bg); }   /* 不存在 */
```

### 1.4 侧栏标签页和大纲条目的高亮色没有生效

`.sidebar-tab:hover` / `.sidebar-tab.active` / `.outline-item:hover` / `.outline-item.active` 都写了 `color: var(--text-primary)`——全部无效，颜色停在继承值。**悬停和选中态只剩背景色变化，字不会提亮**，这正是"点了但好像没点上"的手感来源。

`.sidebar-tab` 还写了 `border-radius: var(--radius-sm)`（无 fallback → 0），而同一份文件 884 行写的是 `var(--radius-sm, 6px)` → 6px。**同一个不存在的 token，两个地方长得不一样。**

→ 修法：`--text-primary` / `--bg-primary` / `--bg` / `--radius-sm` / `--text-tertiary` 全部是历史命名，映射到现有 token（`--text` / `--bg-surface` / `--bg-base` / `--radius` / `--text-muted`）并改用真名。加一条 CI 检查：CSS 里用到的每个自定义属性都必须在 `tokens.css` 里有定义，否则构建失败——这类错误无声无息，只能靠机器挡。

## 2. 6.2 之前写歪的标记还在文件里 · V57

6.2 修好了"拖框拖出页面"，但只修了**产生端**。`pdfRectToBox` 在渲染端**不做任何夹取**：

```ts
return { left: left / w, top: top / h, width: (right-left)/w, height: (bottom-top)/h };
```

于是 6.2 之前画歪的标记（`left` 为负、或 `width` 超过 100%）今天仍然画在页面外，压在邻页上——`.pdf-page-slot` 也没有 `overflow: hidden`（V51 已记）。

→ 修法两层：`pdfRectToBox` 把结果夹进 `[0,1]`（同时保护搜索高亮和链接层），`.pdf-page-slot` 补 `overflow: hidden` 作兜底。已确认 `MarkNote` 弹层渲染在 `PreviewPane` 层级、不在页面槽内，所以加 `overflow` 不会把它裁掉。

**这一条是我上一版没做完的事，不是新发现。**

## 3. 第三处"页面不动"的假设：选区浮动按钮 · V58

`useAskSelection` 只在 `selectionchange` 时计算位置，而**滚动不触发 `selectionchange`**：

```ts
x: rect.left + rect.width / 2,   // 视口坐标，选中那一刻
y: rect.top,
```

配合 `.ask-selection-btn { position: fixed }`——**选中文字后滚动页面，按钮钉在窗口上不动，选区跑了**。

需要说清楚的是：**标记本身是对的**。`rects` 和 `pageBox` 在同一次 `update()` 里一起取，二者之差不受滚动影响，所以点下去落点正确。坏的只是按钮的位置。我不把它说得比实际严重。

同一处还有一个魔数：

```css
.mark-selection-btn {
  /* Sits to the right of "Ask about this", which owns the anchor point. */
  transform: translate(calc(-50% + 74px), calc(-100% - 8px));
}
```

**74px 是"Ask about this"在英文下的宽度**。中文是"就这段提问"，宽度完全不同——两个按钮要么叠在一起，要么中间空一条缝。i18n 的应用不能用像素猜排版。

→ 修法：选区存在时监听容器滚动重算位置（或干脆把按钮放进页面槽、用页面坐标定位）；两个按钮改成一个 flex 容器，间距交给布局而不是 `translate`。

## 4. 设计系统只存在于纸面上 · V59

```
font-size: 直接写 px      193 处
font-size: var(--text-*)   13 处
实际用到的字号            11 种：9,10,11,12,13,14,15,16,18,20,28
其中 10px 用了 27 处，9px 用了 3 处

border-radius token       2 个（--radius:6px, --radius-lg:8px）
实际用到的圆角            10 种：1,2,3,4,5,6,8,10,12,999px

硬编码 hex 颜色           29 处
硬编码 rgba()             39 处
```

一个**阅读**工具里有 27 处 10px、3 处 9px 的文字。这不是紧凑，这是看不清。

再加上结构性的历史包袱：

```
CSS 总量        5,508 行 / 5 个文件（App.css 3222 + AppV3.css 762 + settings 951 + preview 498 + tokens 75）
定义的类名      486 个
从未在 ts/tsx 中出现  119 个（约 24%，含少量 pdf.js 生成的类，真实死类约 110）
跨文件重复的选择器    11 个
```

其中一个是实打实的冲突：

```css
/* preview.css:59 */ .toolbar-btn { height: 28px; padding: 0 6px; ... }
/* App.css:1956  */ .toolbar-btn { font-size: 11px; padding: 4px 8px; }
```

`App.css` 在 `preview.css` **之后**导入，所以工具栏按钮的内边距由**导入顺序**决定，不由设计决定。`AppV3.css` 这个名字本身也说明这里叠着至少三代外壳。

还有 **0 处 `prefers-reduced-motion`**，而全库声明了 44 处 transition/animation——动效关不掉。

→ 修法（这是"现代化和优雅"的实质内容）：
1. 把字号收敛到 token（4 个不够，扩到 6 个：11/12/13/14/16/20），**取消 9px 和 10px**，全部替换；
2. 圆角收敛到 3 个（`--radius-sm: 4px` / `--radius: 6px` / `--radius-lg: 10px`）+ `999px` 药丸；
3. 删掉确认无引用的死类，合并 `AppV3.css` 到 `App.css`，消掉 11 个重复选择器；
4. 补一段 `@media (prefers-reduced-motion: reduce)` 全局关闭动效；
5. 硬编码颜色收进 token。

**代价要说清楚**：这是一次大范围的样式改动，而 jsdom 测不了布局（6.2 已经说明过），所以**这一部分只能靠你在真机上看**。我能保证的是不改变类名与结构、只收敛数值，且每一步可分开提交。
