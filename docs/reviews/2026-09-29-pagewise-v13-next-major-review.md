# 现状复查与 13.0 方向：让回答本身成为证据

*2026-09-29。基线 12.0.0（main `0fffc1b`）。本地 `vitest run`：114 个文件、917 个用例全部通过。*

---

## 0. 结论

1. **工程状态健康，产品方向在打转。** 9.0 → 12.0 四个大版本都在同一条轴上：让*侧栏里的记录*更可信（记下来 → 引文定位 → 视觉规范 → 信任状态与简报）。12.0 已经把这条轴做完整。再加第五轮，只会是修补，谈不上质变。
2. **最大的缺口是：读者看得最多的是回答，而回答没人核对。** 10.0 以来的引文校验（`quote-locate.ts` → `finding-anchors.ts` → `finding-trust.ts`）只作用于 `Finding`，也就是侧栏记录。聊天回答里的"第 5 页"只是 `remark-page-refs.ts` 用正则生成的跳页链接：不带引文，不检查，也不高亮。
3. **13.0 建议的质变：回答里每一条文档事实都带逐字引文，本地自动核对，点开就在页面上高亮原句，核对不上的当场标出来。** 这样"记录"就不再是另一个系统：从回答里留下一句已核对的话，它就是一条 `located` 的 finding。
4. **前置条件：先能量化。** 十二个大版本里，本仓库一直没有办法衡量回答质量或引文定位率（9.2、12.0 的设计文档都写了"无法在本仓库验证"）。13.0 的第 0 包是离线评测基线。它不过门槛，就不做第 1 包。
5. **多文档放到 14.0，而且依赖 13.0。** 多文档的改动面最大（见 §3.2），而且在引文核对之前做，只会把"无法核对的断言"从一份文档放大到 N 份。13.0 的引文格式从第一天起就带文档身份，这样 14.0 是在它上面加东西，而不是返工。

## 1. 现状

### 1.1 做得好的，应当保留

| 方面 | 事实 |
|---|---|
| 测试与守卫 | 114 个测试文件、917 个用例。另有若干守卫：CSS 顺序与 token 检查、工具前缀摘要固定（`agent-tool-prefix.test.ts`）、i18n 占位符测试、bundle 中残留 console 的检查。 |
| 缝隙审计 | `scripts/request-audit.mjs` 抓取 provider 实际收到的请求体。8.1.8 和 9.1 两个"两边测试都绿、在接缝处失效"的缺陷就是这样发现的。 |
| 数据安全 | 12.0 的 `store-migrate.ts`：store 的版本只会前进，来自更高版本的数据放到旁路槽位，不会被清空。 |
| 成本意识 | 系统提示保持字节不变以命中缓存，易变上下文附在用户消息上；同一轮内已读页只回一个短标记；`compact-run-messages` 压缩旧工具结果；推理强度按步调整（9.2.1）。 |
| 信任模型 | `trustOf` 是唯一的计算入口，面板、模型上下文和导出读的是同一个值（12.0）。 |
| 文档习惯 | 每个大版本都有设计文档，并区分"代码确认"和"实测确认"。 |

### 1.2 结构性限制（带代码位置）

**A. 回答不受核对。**
- 引文定位只在 `finding-anchors.ts:141` 调用 `locateQuote`，调用方只有记录。
- 回答里的页码引用由 `remark-page-refs.ts:16` 的正则生成，链接是 `pagewise-page:N`，不带引文，也不带文档标识。
- 系统提示要求"quote short key passages verbatim"（`agent.ts`），但格式是自由的，程序无法识别哪一段是引文。
- 后果：同一句话写进记录会被核对，写在回答里就不会。

**B. 检索只有精确子串。**
- `document-search.ts:47-95` 是大小写折叠加 NFC 之后的 `indexOf`，没有分词、排序和模糊匹配，结果按页序返回，默认 12 条。
- 换一种说法提问（查"违约责任"，原文写的是"违反本合同的后果"）会零命中。之后 agent 只能靠 outline 和整段阅读（每轮 20 万字符预算）去硬找。

**C. "一份活动文档"写死在很多地方。**
- `doc-cache.ts:10` 设了 `MAX_CACHED_DOCS = 1`；`pdf.ts:34` 只有一个 pdf.js 句柄。
- `SessionProvider.switchDocument` 切换文档时整套拆除；系统提示写着 "The user has one active PDF"。
- 8 个工具里有 5 个不接受 `path` 参数。
- `agent-view-context`、`agent-steer`、`agent-abort` 都是模块级单例。
- 对话以 path 为键，跨文档的对话没有可用的键。

**D. 无法度量。**
- 没有真实文档语料，也没有录制下来的模型输出，所以无法回答"回答对不对""引文定位率多少""换检索算法之后好了还是坏了"。
- 夹具（`src-tauri/tests/fixtures/`）是 8 个几页长的小 PDF，用来测功能，不能用来度量。
- 4.4 那次实测（整句引文 24% 可定位）用的是已经废弃的匹配路径；10.0 之后的折叠匹配**从未在长文档上测过定位率**。

**E. 小问题（不构成版本，顺手修）。**
- `index-store.ts:171-175` 的 `loadIndexedPages` 按 `path + stamp` 精确匹配，没有 12.0 给其他 store 加的 identity 回退。文件改名后，已经付费的视觉识别结果会失效并重新计费。
- 版本号膨胀：11.0 是一次视觉规范，按 semver 应当是 minor。建议 13.0 起只有数据格式或核心交互变化才升大版本。

## 2. 13.0：有出处的回答

### 2.1 目标句（验收单位）

> 读者问一个问题，回答里每一条来自文档的事实后面都带一个引用标记。点开，页面跳到那一页，把那句原话高亮出来。PageWise 在本地核对过的引用显示为已核对；核对不上的当场显示为"未在该页找到"；只给了页码、没给原话的，显示为"仅页码"。回答底部一行写明"8 处引用，7 处已在原文定位"。

这是质变而不是加功能，理由有三：
- **信任的对象从侧栏移到主界面**，读者读的每个回答都带核对结果。
- **核对是确定性的**：本地完成，不需要额外的模型调用，不花钱。
- **记录与回答合流**：点"留下"不再是摘 500 字，而是挑出已核对的句子。每句自带 `pages + evidence + located`，直接是一条可信的 finding。

### 2.2 引用格式

模型在回答中写：

```
合同约定逾期付款按日万分之五计息〔p12 "按日万分之五计收违约金"〕。
```

- 用 `〔` 和 `〕` 作界符：中英文正文里几乎不出现，流式输出时容易增量解析，模型也容易照着写。
- 结构：`p<页码或印刷页码> "<逐字引文>"`。引文可以省略，省略时只做跳页，状态为"仅页码"。
- **预留文档字段**：写成 `〔d2 p12 "…"〕` 时，`d2` 是本轮会话的文档短句柄。13.0 只有一份文档，省略即可；14.0 直接启用。
- 新增 remark 插件 `remark-citations`，放在 `remark-page-refs` 之前运行。旧格式的"第 N 页"继续生效，历史对话不受影响。

### 2.3 核对管线（复用现有部件）

```
流式文本 → remark-citations 解析出 {page, quote}
        → citation-anchors（参照 finding-anchors：按 messageId#index 缓存，只在该页的 page_text_items 上跑 locateQuote）
        → CitationTrust = located | unlocated | unreadable | pageOnly | outOfRange
        → 渲染：上标标记加状态色；点击跳页，由 FindingLayer 的同一套高亮画出矩形
```

- 规则与 12.0 相同：只在**被引用的那一页**上查找，不做全文搜索（理由见 `quote-locate.ts:111-115`）。
- 页上没有文字层时，状态是 `unreadable`，**不能**判为 `unlocated`（12.0 的教训）。
- `outOfRange` 复用 `note_finding` 的越界检查。
- 流式期间只解析、不核对，一条消息结束后统一核对，避免一边输出一边闪烁。

### 2.4 模型侧

- 系统提示加一条规则，说明引用格式；删掉原来那句"quote … verbatim"。这会让缓存前缀失效一次（约 1,472 token 的前缀），属于一次性代价。
- 工具前缀摘要测试随之更新。
- `note_finding.evidence` 与引用格式统一，模型记下的依据就是它引用的原话。
- **核对结果回传给模型**：下一轮的易变上下文附一行"上一回答中 p12 的引用未在原文定位"，让模型有机会自行更正。代价是每条未定位引用几十个 token。

### 2.5 界面

- 回答页脚：`引用 8 · 已定位 7 · 仅页码 1`。有未定位的引用时，这一段改用警示色。
- 每个引用标记显示状态色。悬停时预览原句；未定位的，预览模型声称的原话，并附一句"未在第 12 页找到这段文字"。
- "留下"改为两种：留下整个回答（现状），或只留下已核对的句子（新增，勾选）。
- 11.0 的状态规范不动，只新增引用标记这一种元素。

## 3. 交付包与顺序

### 包 0 · 度量基线（阻塞后续所有包）

- `eval/corpus/`：放 5–8 份许可允许的真实长文档，覆盖中文合同、英文论文、带公式的教材、扫描件、表格密集的年报，并记录来源与许可。
- `eval/questions.jsonl`：每份文档 10–20 个问题，写明预期页码与原文片段。
- `scripts/eval-run.mjs`：对真实 provider 发起请求，**录制**完整回答（需要本地 API key，不进 CI）。另有 `eval-score.mjs` 对录制结果做离线打分，这一步可以进 CI。
- 指标：
  - 引用覆盖率（带引文的事实句 / 事实句）；
  - 引文定位率（located / 带引文）；
  - 页码命中率（引用页 ∈ 预期页）；
  - 每题花费的 token 与步数。
- **门槛**：对"模型确实逐字照抄的引文"，prose 类文档的定位率 ≥ 90%。达不到，先修 `locateQuote`（例如连字、全角半角、引号风格的折叠），不进入包 1。
- 这一包也把 9.2 以来"模型行为无法验证"的问题一并解决：此后所有改提示词、改工具的决定，都要附录制对比。

### 包 1 · 引用格式与解析
按 §2.2 实现 `remark-citations` 和流式增量解析。旧的页码引用保持兼容。

### 包 2 · 核对与展示
按 §2.3 和 §2.5 实现 `citation-anchors`、`CitationTrust`、上标标记、页脚统计和跳页高亮。

### 包 3 · 回到模型，并与记录合流
按 §2.4 实现。增加"只留已核对句子"的留下方式。导出的简报按引用状态分组（直接复用 `export-brief`）。

### 包 4（可独立并行）· 检索排序
- `document-search` 从按页序的子串匹配改为 BM25 排序：英文分词，中文用二元组切分，纯本地，不引入依赖。
- 用包 0 的语料对比改动前后的页码命中率，**不提升不合入**。
- 语义向量检索（embedding）不进 13.0：它需要选择本地模型或把全文发给 embedding API，隐私和体积都要单独做决定。

### 顺手修（13.0.x）
- `index-store` 加 identity 回退（§1.2 E）。

## 4. 验收

1. **（自动化）** 解析：给定含 30 个引用、跨越流式分块边界的回答，解析结果逐项正确；旧格式的"第 N 页"仍然生成链接。
2. **（自动化）** 核对边界：文字页、扫描页、IPC 失败、越界页、省略引文五组，分别得到 `located / unreadable / unreadable / outOfRange / pageOnly`。任何一组得到 `unlocated` 即失败。
3. **（自动化，request-audit）** 上一轮有未定位引用时，本轮请求的用户消息里出现对应的提示行；系统提示字节不变。
4. **（离线评测）** 包 0 的门槛；13.0 发布版本的定位率、覆盖率与 12.0 基线的对比写进 CHANGELOG。
5. **（手动，UI harness）** 点击引用标记，页面上高亮的矩形与原文的位置一致；深色和浅色主题都要截图。

**主指标**：包 0 语料上，回答中"已定位引用 / 全部文档事实句"的比例。12.0 的这个值按定义是 0，因为回答从不核对。

## 5. 候选对比：为什么不是别的

| 候选 | 是否质变 | 改动面 | 判断 |
|---|---|---|---|
| **有出处的回答（本文）** | 是：信任对象从侧栏移到主界面 | 中：定位、高亮、信任三块都已存在 | **13.0** |
| 多文档工作集 / 对照 | 是：作用范围从一份变成 N 份 | 大：§1.2 C 列出的十余处 | **14.0**。先有可核对的引用，否则跨文档断言无法区分真假；引用格式已预留 `d<n>`。 |
| 语义检索 | 否：是基础设施，读者感知不到 | 中，另需隐私决策 | 13.0 只做 BM25（包 4）；向量检索与 14.0 一起评估。 |
| 自动 OCR 扫描页 | 否 | 小 | 仍然需要读者授权才调用视觉模型（12.0 的判断不变）。 |
| 更多格式（docx/epub/html） | 否：换一种输入 | 中，需要新的提取器 | 等"有出处的回答"成立之后再扩展，否则每种新格式都要单独补一遍核对。 |
| 继续打磨记录 | 否 | 小 | 9–12 已经做完整，边际收益低。 |

## 6. 风险

- **模型不照格式写。** 弱模型可能漏掉 `〔〕` 或改写引文。对策：
  - 包 0 录制多个模型的输出，按模型给出覆盖率；
  - 不守格式的回答照常渲染，只是统计栏会显示"仅页码"或"无引用"，这本身就是对模型的如实评价；
  - `model-capabilities` 可以对已知弱模型关闭统计栏，避免满屏警告。
- **引用增加输出 token。** 每条引用约 15–40 token。一个回答 8 条引用，约多 300 token。按包 0 实测记录，超出 10% 时收紧"只在事实句引用"的措辞。
- **"未定位"被读成"模型撒谎"。** 断字、连字、公式等提取差异也会导致未定位。文案沿用 12.0：写"未在该页可提取文本中找到"，不写"引文不存在"。同时，包 0 的门槛保证这类误报在 10% 以内。
- **评测语料的许可。** 只收公开许可的文档；如果做不到，语料不入库，改用本地路径配置。
